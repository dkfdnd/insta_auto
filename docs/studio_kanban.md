# 제작실 칸반과 상세 편집

제작실은 실제 파이프라인과 같은 소스 확보 → 원본 발화 → 제작 대본 → 음성 제작 → 영상 편집 → 내보내기의 여섯 열로 표시한다. 완료 작업은 내보내기 열에 남고 제작 완료 필터에서 따로 볼 수 있다. 카드는 실제 작업 상태를 읽어 자동 배치하며 드래그로 제작 단계를 변경하지 않는다.

## 단계와 실행 상태

`web/studio-board.js`의 `describe()`가 목록과 필터에 사용하는 표시 모델을 만든다. 기존 `/api/studio` 응답을 사용하며 DB나 실행 큐 계약은 변경하지 않는다.

- 단계는 작업의 `status`를 우선하고, 오류·일시중지·외부 대기는 `automation.stage` 또는 관련 실행 작업으로 원래 단계를 찾는다.
- 회전 표시는 `jobs[].status === running`인 실제 작업에만 적용한다. 큐 대기, CapCut 종료 대기, 자동 재시도 대기는 처리 중으로 집계하지 않는다.
- 추가 소스 수집·AI 수정안 생성은 보조 작업이다. 이 작업이 실행되어도 본 제작 단계는 유지한다.
- `script_review`, `voice_review`, `draft_review`는 사람의 검토 대기다. `completed`는 실제 MP4 내보내기 완료이며 사람의 최종 승인 여부를 뜻하지 않는다.
- 오류 카드는 해당 제작 단계에 남고 확인 필요 필터로 모아 볼 수 있다.
- 재제작은 현재 실행 버전의 단계로 돌아간다. 이전 완료본이 있으면 카드에 함께 표시하고 결과·이력 탭에서 계속 열 수 있다.

## 상세 패널

카드에는 단계 번호(`4 / 6 단계`), 연결된 원형 진행 표시, 현재 작업 설명과 하단 작업 버튼이 표시된다. 완료 단계는 채워진 체크, 현재 단계는 테두리 원, 남은 단계는 빈 원이다. 실제 실행 중인 현재 단계만 은은하게 반복 강조한다. 소요 시간의 비율을 임의로 표시하지 않으며, 완료된 단계 수는 현재 버전의 결과에 근거한다.

카드를 누르면 왼쪽 세로 진행 목록이 있는 우측 패널이 열리며 소스 / 대본 / 음성 / 편집 / 결과·이력으로 전환할 수 있다. 처음에는 제작 단계에 맞는 탭을 선택하며, 이후 자동 진행이 탭을 강제로 바꾸지 않는다.

- 전체화면 확장과 모바일 화면에서는 배경을 비활성화하고 패널 안에서 키보드 포커스를 이동한다.
- Escape 또는 닫기 버튼으로 보드에 돌아간다. 장면 후보·대본 비교 대화상자가 열려 있으면 그 대화상자를 먼저 닫는다.
- 탭 전환 시 편집 DOM을 유지한다. 작업별 패널과 스크롤 위치를 보관하고, 패널을 닫거나 다른 작업으로 이동하면 미디어 재생은 멈춘다.
- 자동 제작 피드백은 기존 localStorage 초안과 `feedback_revision` 충돌 검사를 유지한다. 피드백 저장과 실제 재제작은 별도 동작이다.
- 수동 작업의 대본은 기존 자동 저장 및 승인 절차를 유지한다.
- `?work=작업ID` 직접 링크로 같은 작업을 열 수 있다.

## 갱신과 접근성

3초 간격 조회는 유지하되 카드의 DOM은 ID별로 재사용하고 바뀐 텍스트·상태만 갱신한다. 단계가 바뀔 때만 카드를 다른 열로 이동한다. 입력, 재생, 미디어 탐색 중인 상세 화면은 전체 교체를 피한다.

단계 이동에 짧은 강조 효과를 사용하고 처리 중 아이콘은 회전한다. `prefers-reduced-motion`에서는 애니메이션을 끈다. 연결 오류 시 마지막으로 확인한 상태라는 안내를 표시하고 보드의 회전 표시를 멈춘다. 썸네일은 기존 편집 커버 또는 로컬 `web/thumbs/` 파일을 사용하며 없는 파일은 기본 이미지로 대체한다.

## 검증

```bash
node --test tests/studio_board.test.cjs
.venv/bin/python -m pytest -q tests/test_studio_board_browser.py tests/test_production_flow_browser.py
node --check web/studio.js
node --check web/studio-board.js
node --check web/production-flow.js
```

브라우저 회귀 시험은 별도의 API fixture로 실제 제작실 HTML/JS/CSS를 연다. 사용자의 DB와 제작 큐를 실행하거나 변경하지 않는다. 단계 이동, 필터, DOM 유지, 피드백 저장, 수동 승인, 버전 선택, 입력·재생 위치·스크롤 보존, 모바일, 키보드와 모션 감소를 확인한다.

이전 칸반 구현(`284b536`)의 macOS 검증: Python 시험 245개 통과, 2개 실패. 진행 표시 개편은 별도 상태 시험으로 확인하며 브라우저에서 단계별 표기와 레이아웃을 다시 검증해야 한다. 제한된 세션에서는 Chrome 실행이 차단되어 브라우저 시험을 완료하지 못했다. 다음 두 기존 시험은 변경 전 `857fd3a`에서도 동일하게 실패했다. 이번 화면 변경의 회귀와 구분한다.

- `test_server_can_bind_multiple_explicit_interfaces`: 로컬 `127.0.0.2` 인터페이스에 bind할 수 없음.
- `test_virtualenv_tool_is_found_beside_python`: macOS에서 Windows `.exe` 도구 탐색을 기대하는 시험.
