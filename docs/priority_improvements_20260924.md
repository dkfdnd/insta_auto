# 우선순위 개선 및 검증 — 2026-09-24

## 1. 수집과 기준선

- 최초/표본 부족 계정: 최대 31개 메타데이터 확보. 평소에는 최신 5개 갱신.
- 웹 수집기는 마지막으로 저장한 최신 게시물까지 기본 최대 60개 범위에서 페이지를 진행한다.
  과거 고정 게시물에 닿았다는 이유로 중단하지 않는다. 더 큰 공백은 경고하며 무제한 요청하지 않는다.
- 조회수 요청 예산: 최신 5개 + 기준선 누락 최대 10개. 남은 기준선 조회수는 후속 실행에서 보강한다.
- 아직 핫이 아닌 게시 후 14일 이내 릴스도 마지막 시도가 오래된 순서로 최대 5개를 순환 조회한다.
  기존 핫 릴스 추적을 유지하고 429 관측 후 같은 계정의 추가 조회는 중단한다.
- Windows 작업 스케줄러 설치/상태/삭제를 지원한다. 현재 사용자 일반 권한, 로그인 상태에서 실행한다.
  기본 07:00이며 놓친 일정 재개, 중복 실행 방지, UTF-8 로그, 숨김 실행을 적용한다.

## 2. 잠정 후보와 성과 확인

기존 tier/배수는 유지하고 `assessment`를 추가했다. `confirmed`는 보정 전 배수도 기준을 통과하고,
같은 유형 표본이 기본 8개 이상이며 지표가 누락되지 않아야 한다. 영상은 조회수 기준선도 8개 이상,
3시간 이상 간격의 성공 관측 2회 이상, 마지막 성공 관측 30시간 이내, 마지막 시도 성공이 필요하다.
그 밖의 기준 통과 영상은 `provisional`이다. 일반 영상은 `normal`이다.

대시보드는 두 상태를 별도로 집계/필터하고 상세 화면에 보정 전 배수와 부족한 근거를 표시한다.
확인 대상은 계정의 평소 대비 상대 성과다. 절대적인 바이럴, 시청 유지율 또는 구매 전환을 보장하지 않는다.

## 3. 소스 탐색과 다운로드

- 모든 공급자의 URL에 영상 상세 URL 검증을 적용한다. 검색/쇼핑/해시태그 페이지에 다운로드 예산을 쓰지 않는다.
- YouTube watch/Shorts/단축 URL을 같은 영상 ID로 중복 제거한다.
- 다운로드 실패 시 다음 후보로 진행한다. 성공 검사 수, 총 시도, 시간 예산을 별도로 관리한다.
- 플랫폼별 발견/수신/선정 수와 예산 중단 사유를 manifest에 남긴다.
- 같은 제품의 다른 구도 영상(product)과 동일 장면 검색(scene)을 설정으로 구분한다.
- 의미 임베딩만 높은 영상은 중복으로 버리지 않는다. 파일/여러 장면 지문으로 중복을 확인한다.
- 기존 기준 영상을 검증 후 재사용하고 CUDA 사용 가능한 환경에서는 OpenCLIP에 CUDA를 사용한다.
- Tesseract가 없으면 저장된 EasyOCR ko+en 모델을 사용한다. Windows 한글 경로는 이미지 bytes로 전달한다.
  읽기 어려운 텍스트가 반복되면 클린으로 오인하지 않으며, @작성자 표시는 위치와 무관하게 워터마크로 취급한다.
- 외부 프로그램의 혼합 문자 인코딩이나 개별 다운로드 예외가 전체 작업을 중단하지 않도록 처리했다.

## 4. 다국어 검색

캡션·저장된 음성·화면 OCR·Vision 라벨에서 제품 종류, 브랜드, 관측된 특징과 명시된 모델/품번을 추출한다.
제품을 식별할 수 없을 때 OpenCLIP 카탈로그를 보완 근거로 쓴다. 검색 의도는 제품, 브랜드 제외, 외형,
상세 리뷰, 사용 시연, 개봉이며 영어·중국어·한국어와 근거를 각각 보존한다.

예: 기존 `travel organizer bag` / `旅行收纳袋` 대신 실제 저장된 캡션·음성에서 확인되는 백팩·아디다스·나일론을
사용해 `adidas nylon backpack`, `阿迪达斯 尼龙 双肩包`, `阿迪达斯 双肩包 开箱 实拍` 등을 생성한다.
품번은 관측한 문자열에서만 추출하며 임의로 만들지 않는다. 현재는 규칙·사전 기반이고 범용 자동 번역은 아니다.

중국 플랫폼에는 전체 검색어 중 중국어 풀을 선택한다. 영어 중심 플랫폼은 영어와 보조 언어를 분배한다.
관련성이 검증된 후보 제목에서 새 이름/품번을 얻으면 YouTube 추가 탐색을 한 번 진행한다.

## 검증 범위

- 회귀 테스트: 초기 기준선, 고정 게시물이 포함된 수집 공백, 과거 조회수 예산, 순환 관측,
  잠정/확인 분류, 다국어·품번 근거, 비영상 URL, 성공 검사 예산, Windows 작업 인자,
  한글 경로 OCR, 읽지 못한 외국어 텍스트와 워터마크, 혼합 인코딩을 검증한다.
- Chrome 실제 화면: 임시 DB로 성과 확인 1개/잠정 후보 1개를 표시하고 필터·상세 보정 전 배수,
  JavaScript 오류 부재를 확인했다. 운영 DB를 UI 테스트용 데이터로 바꾸지 않았다.
- 운영 DB를 백업한 뒤 기존 계정 1개 수집을 시도했지만 Instagram 리디렉션 반복으로 실패했다.
  게시물 데이터는 보존됐으며 로그인/계정 확인 상태 점검과 세션 갱신이 필요하다.
- 이 PC에 EasyOCR 검출/한국어·영어 인식 모델을 준비했다. 저장된 기준 프레임과 후보를 실제로 재검사했다.
- 최종 전체 테스트 78개, Python 컴파일, JavaScript 문법, diff 공백 검사가 통과했다.
- 제한된 실제 검색(초기 후보 12개, 성공 검사 4개, 최종 상한 3개): 5회 시도 → 4개 수신 → 3개 ZIP.
  최종 분류는 약한 오버레이 2개, OCR 미검증 1개, 클린 확정 0개다. 기존 영상 캐시 재사용을 포함하므로
  새 영상 3개를 발견했다거나 전체 검색 성공률이 개선됐다는 증거로 해석하지 않는다.
- 운영 리포트를 재생성했다. 기존 34개 게시물에서 기준 통과 4개는 모두 잠정 후보이며 성과 확인은 0개다.
- 검토용 로컬 서버에서 `/`, `/api/criteria`, `/api/collection-status`가 HTTP 200을 반환했다.

외부 서비스 상태와 대표 표본의 실제 성과는 단위 테스트가 보장하지 않는다. 수집 세션 복구 후
게시 연령별 관측을 축적하고, 다양한 제품의 대표 릴스 20~30개에서 고유한 유효 소스 수·정확도·소요 시간을 비교해야 한다.
검색량 증가가 실제 사용 가능한 소스 수 증가로 이어지는지는 이 평가를 통해 판단한다.
