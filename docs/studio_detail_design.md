# 제작 상세 화면의 UI 기준

대상은 쇼츠 제작이나 컴퓨터 사용에 익숙하지 않은 40–50대 사용자다. 사용자의 우선 목적은 완성 영상 재생과 다운로드다. 게시물 상세는 결과 확인 화면, 제작실은 수정 화면으로 구분한다. API 경계와 선택 대본·음성, 제작 이력을 유지한다.

## 게시물 상세 — 2026-10-05 합의 반영

1. 맨 위에는 **소스 영상 → 대본 → 음성 → 완성 영상** 네 박스를 둔다. 원본 발화 추출과 대본 제작, 편집과 내보내기는 각각 하나로 합쳐 표시한다. 완료·대기·오류 여부와 관계없이 전부 누를 수 있고, 누르는 동작은 조회만 수행한다.
2. 박스 아래 선택한 단계의 요약을 펼친다. 다시 누르면 접힌다. 소스는 실제 사용 가능한 중복 제외 개수와 플랫폼별 개수, 대본은 현재 선택된 본문, 음성은 해당 대본으로 만든 오디오를 보여준다. 중간 파일 다운로드와 수정은 제작실에서 한다.
3. 결과는 원본 왼쪽 / 우리 완성본 오른쪽의 가로 비교다. 모바일도 좌우 배치를 유지하며 재생·전체 화면 버튼을 제공한다. 자동 재생하지 않으며 재생을 누르면 소리가 난다. 한 번에 하나의 미디어만 재생한다. 다운로드는 보이는 결과와 같은 제작 버전을 가리킨다.
4. 신규 제작 상태가 맨 위다. 기존 완성본은 그 아래 최신순으로 계속 보이며 처음에는 펼쳐 둔다. 각 영상의 ‘접기 / 펼치기’ 버튼 상태를 보존한다. 재제작 실패로 기존 완성본을 숨기거나 없애지 않는다.
5. 오류 상세·원본 메타데이터·용어는 아래 접기 영역에 둔다. 영상보다 먼저 버전 설명이나 승인 안내를 내세우지 않는다. 자동 Top Pick 대본에는 승인 과정이 없다.
6. 폴링 중에는 기존 플레이어 노드와 부모를 유지한다. 새 완성본을 추가하거나 다운로드 링크가 바뀌어도 다른 영상의 재생 위치·음량·재생 상태를 초기화하지 않는다. 펼친 단계·영상 이력도 유지한다. 연결 실패 시 마지막 결과를 지우지 않는다.

완료는 **녹색 + 체크 + 완료**, 대기는 **회색 + 대기**, 실패는 **진한 빨강 + 느낌표 + 실패**, 실제 실행 작업만 **파랑 + 스피너 + 진행 중**으로 표현한다. 소스 수집과 음성이 동시에 실행되면 두 박스 모두 진행 중이다. 단순히 서비스가 켜져 있다는 이유로 스피너를 표시하지 않는다.

소스 목표는 플랫폼 합산 최소 10개다. 플랫폼별 할당량은 없다. 핵심 기능 장면을 포함하며, 적합한 요리·활용 장면은 보조 영상으로 인정한다. 사용자에게 부족한 영상을 직접 찾아 달라고 요청하지 않는다. 현재 목표 개수보다 적었던 과거 완성본의 완료 상태를 소급 취소하지 않는다.

## 제작실의 수정 도구

- 탭은 **사용할 영상 / 내 대본 / 내 목소리 / 장면·자막 / 완성 영상**이다. 작업 메뉴와 내부 제작 단계의 개수를 같은 숫자로 표시하지 않는다.
- 상태 카드에는 현재 상태, 멈춘 이유, 가능한 행동을 표시한다. 사용자 인증이나 개인 음성 설정이 필요한 경우만 해당 설정으로 안내한다. 부족한 소스는 자동 추가 수집한다.
- 실행 중에는 실제 `running` 작업에만 움직임을 표시한다. 대기·준비 부족·연결 실패에는 실행 중인 것처럼 표시하지 않는다.
- 완료는 녹색과 ‘완료’ 글자를 함께 사용한다. 선택한 탭과 완료 상태는 서로 다른 의미다.
- 대본은 전체 행을 누를 수 있는 **대본 보기** 버튼으로 연다. 펼친 내용은 제목, 테두리, 배경과 읽기 쉬운 문단을 갖춘 카드다.
- 대본·영상 선택·목소리 설정 수정은 **수정 내용으로 영상 만들기** 한 번으로 저장과 제작을 요청한다. 설정만 저장하는 도구는 상세 영역에 둔다.
- 자막 수정은 화면 글자만 바꾼다. 실제 대사는 ‘내 대본’에서 바꾼다는 설명과 이동 버튼을 노출한다.
- 완성 탭은 원본과 선택된 제작 버전의 실제 영상을 재생하고, 해당 버전의 영상만 내려받는다. 번호·완료 여부·한국 시간의 저장 시각과 확인 가능한 변경 내용으로 버전을 구분한다. 근거가 없으면 ‘다시 제작’으로 표시한다.

## 추가 정보와 버튼

후보·이전 대본, 원본 전사/OCR, 검색 기록, 발음 규칙, 타임라인, 제작 자료 파일, CapCut 도구는 명확한 ‘보기’ 버튼 또는 접기 영역에 둔다. 다만 해결해야 할 오류·입력 충돌·필수 준비는 숨기지 않는다.

주요 클릭 영역은 48px 이상, 본문은 16px 이상, 버튼은 18px, 읽는 대본은 20px를 기본으로 한다. 48px는 이 서비스의 편안한 조작 목표이며 모든 웹 사이트의 법정 최소 크기라는 뜻이 아니다. 클릭 영역의 간격은 8px 이상으로 잡는다. 밝은/어두운 테마의 본문·주요 버튼 색 대비는 4.5:1 이상을 검사한다. 키보드 초점, `aria-expanded`/`aria-controls`, 미디어의 기본 재생 제어, 동작 줄이기 설정을 유지한다.

정적 하단 제작 영역을 사용해 확대 글자와 모바일 화면에서 입력창이 고정 버튼에 가려지지 않게 한다. 접은/펼친 상태와 미저장 입력, 업로드 큐, 재생 위치는 데이터 갱신 중 보존한다. 수동 제작의 실제 대본·음성 선택 절차는 유지하되 원본/이력/추가 도구를 같은 접기 체계로 정리한다.

## 적용한 스킬과 검토 근거

사용자가 지정한 [UI/UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)의 `SKILL.md`, `references/pro-rules.md`, `references/quick-reference.md`를 읽고 적용했다. 읽기 편한 글자·대비, 충분한 조작 영역, 명확한 행동 이름, 피드백과 단계적 정보 공개를 사용한다.

스킬 검색에서 touch target 관련 지침은 일치하는 결과를 확인했다. progressive disclosure 검색은 재시도 후 일치 결과가 없었으므로 검색 DB의 추천이라고 주장하지 않고 quick-reference의 §8 기본 지침을 적용했다. 디자인 시스템 검색에서 얻은 미니멀한 구성은 사용하되, 앱에 맞지 않는 랜딩 페이지 패턴·라틴 글꼴·제안된 보라색 팔레트는 적용하지 않았다. 기존 한국어 글꼴과 파랑/녹색 상태 체계를 유지한다.

이전 개편의 초보자 리뷰만으로 결과 우선 배치가 충족되었다고 판단하지 않는다. 이번 합의안은 별도 리뷰에서 플레이어 재생 유지, 이전 버전 링크의 초기 선택, 실제 실행 상태 표시를 다시 검토하고 지적을 수정했다. 두 개의 완료 버전 중 과거 버전으로 직접 진입했을 때 재생·다운로드가 모두 같은 버전인지 DOM 테스트로 검증한다.

검증은 JavaScript 단위 테스트, 실제 API 작업 데이터 렌더링, HTML 요소/접기 연결/입력 이름 검사와 정적 파일 제공 확인으로 한다. 저장된 브라우저 origin 차단으로 실제 브라우저 배치·클릭·375px/200% 확대 시각 검증은 수행하지 못했다. DOM 기반 모의 사용성 검토를 실제 사용자 시험이나 시각 검증으로 표현하지 않는다.
