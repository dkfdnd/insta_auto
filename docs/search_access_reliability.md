# 검색 인증 반복 문제 점검 (2026-10-05)

## 사용자 검색 화면 확인 (2026-10-08)

진단에서 CAPTCHA 대기를 0초로 덮어쓴 것이 검색 창을 바로 닫은 원인이었다.
홈 재생과 수집 검색을 구분한다. `POST /api/platform-session`에 TikTok과
`verification_query`를 지정하면 수집 프로필의 검색 화면을 한 번 열고, 검색 결과나
CAPTCHA가 나와도 닫지 않는다. 사용자가 세션 저장 완료를 누르거나 직접 창을 닫을
때까지 기존 로그인 창의 최대 10분 범위에서 유지한다. 새 검색·스크롤·인증 자동
해결은 하지 않는다. 수집 프로필이 사용 중이면 충돌시키지 않고 이유를 반환한다.
일반 플랫폼 로그인은 기존 비동기 전용 프로필 방식으로 즉시 열린다.

실제 검색 응답의 영상 결과 또는 명시적인 빈 결과와 사용자의 완료 동작을 확인해야
재검증을 허용한다. 홈 이동, 로딩 중, CAPTCHA 유지, 시간 만료는 인증 완료 증거로
쓰지 않는다. 검색 응답 확인 중 별도의 `/login` HTTP 요청도 보내지 않는다.

## 공개 검색 링크·레퍼런스 근거 보정 (2026-10-08)

- 실제 Bing 응답의 결과 링크가 `/ck/a`의 `u=a1...` 형식으로 제공됨을 확인했다.
  이동 링크를 그대로 영상 URL 검사에 넘기던 결함을 수정한다. 네트워크 이동 없이
  해당 Bing 도메인의 매개변수만 해석하며, 지원되는 영상 상세 주소만 후보로 허용한다.
  이는 후보 링크 처리 수정이며 로그인·CAPTCHA 차단 해제를 뜻하지 않는다.
- 공개 검색 응답에 보이는 링크 수와 해석된 영상 링크 수를 검색 기록에 남긴다.
  실제 검색에서 지원 영상 링크가 없으면 계속 후보 0개로 기록한다. 모의 링크 검사
  통과를 실제 영상 확보 성공으로 보고하지 않는다.
- 화면 레퍼런스를 별도 검증한 경우, 소스 검색에서도 같은 원본·프레임 해시가
  일치하는 문구만 화면 근거로 재사용한다. 무관한 배경 가사를 검색의 제품 근거에
  넣지 않고, 기존 음성 전사와 OCR 파일은 보존한다. 유효한 검증 결과가 없는 원본의
  음성·OCR 자료는 기존 경로로 유지하며 화면 OCR을 음성 발화로 승격하지 않는다.

## 확인한 사실과 아직 확인하지 못한 원인

- 검색 간격은 이미 30초였다. 속도만 원인이라고 단정할 증거는 없다.
- 최근 24시간 manifest의 검색 기록에는 Google Lens CAPTCHA 8건, TikTok CAPTCHA 10건, 브라우저 강제 시간 종료 7건이 있었다. 이는 시도 기록 수이며 고유 영상 수가 아니다.
- 더우인 `no_results` 기록은 49건이었다. 실제 확인한 저장 화면에는 `登录后即可搜索更多精彩视频`가 있었다. 이 화면은 로그인 요구이고, 함께 보이는 `验证码登录`는 SMS 로그인 방식의 이름이다. 이것만으로 슬라이더 CAPTCHA라고 판단할 수 없다.
- 기존 CAPTCHA 기록은 10분 뒤 만료되어 다음 수집에서 다시 접근할 수 있었다. 인증을 완료했다는 증거 없이 시간이 지났다는 이유로 재검색한 결함이다.
- 브라우저를 부모 프로세스에서 강제 종료하면 자식의 finally에 있는 쿠키 내보내기와 정상 종료가 실행되지 않을 수 있었다. 모든 인증 문제의 원인이라고 입증된 것은 아니다.
- 로그인과 수집이 같은 프로필을 쓰지만 locale은 ko-KR/en-US로 달랐다. 동일 설정으로 정리했다. 언어 차이가 차단의 직접 원인이라는 증거는 없다.
- 점검 시 활성 VPN 어댑터, Windows 프록시, HTTP(S)_PROXY 환경변수는 확인되지 않았다. 공유 IP나 통신사 측 상태까지 배제한 것은 아니다.

## 적용한 동작

1. CAPTCHA, 로그인 요구, 429, 실제 빈 검색 결과를 구분한다. SMS 로그인 문구만으로 CAPTCHA로 판정하지 않는다. 결과 없이 메뉴만 있는 미완성 검색 화면은 `page_unresolved`로 기록하고 해당 회차의 연속 검색을 멈춘다.
2. CAPTCHA/로그인 요구는 해당 공급자만 인증 확인 전 자동 재접근하지 않는다. 다른 공급자는 계속 검색한다. 고정 10분 휴식의 연장이 아니다. 429 휴식 상한은 기존 10분이다.
3. 설정의 플랫폼 로그인 관리에 Google 검색 인증을 추가했다. 사용자가 같은 전용 프로필에서 인증 후 `세션 저장 완료`를 누르고, 플랫폼 페이지가 정상적으로 열려 있으며 화면의 인증/로그인 요구가 사라진 경우 다음 검색 확인을 허용한다. 시간이 지나 자동 저장된 것만으로는 해제하지 않는다. 다음 검색에서 다시 차단되면 다시 중지한다. 세션 저장은 인증 성공이나 CAPTCHA 영구 해소를 의미하지 않는다.
4. 매 검색 전 수행하던 별도 HTTP 로그인 확인 요청을 제거했다. 필요한 검색 응답 자체에서 접근 상태를 확인한다. 실패한 검색어는 인증 복구 후 다시 검색할 수 있다.
5. 검색 예산 종료 전에 정상 저장·종료하도록 협력적 종료를 추가했다. 중간 후보는 보존한다. 완전히 응답하지 않는 브라우저에는 기존의 소유 프로세스 제한 종료가 마지막 보호 수단으로 남는다.
6. 프로필 쿠키 DB를 읽지 못한 경우 로그인 실패로 단정하지 않고 미확인으로 표시한다. 기존 세션·파일·목소리 선택은 삭제하거나 바꾸지 않는다.

## 근본적인 운영 방향

일반 소비자용 검색 화면의 자동 조작을 유일한 수집 경로로 두면 무인 운영을 보장할 수 없다. 검색 후보 발견을 공식 API와 제공받은 자료 저장소로 분산하고, 검색 결과 캐시와 기존 소스 재사용을 유지하는 방향이 적합하다. 플랫폼 접근 허용과 실제 영상 사용 권한은 별도로 확인한다.

- Google: 기존 `search_google_vision` 연결부로 Cloud Vision Web Detection을 사용할 수 있으나 현재 키는 미설정이다. 이는 웹 이미지·일치 페이지 탐색으로, Google Lens 전체 기능이나 영상 다운로드를 대체한다고 보장하지 않는다.
- 텍스트 영상 검색: Brave Video Search API를 후보로 검토할 수 있다. API 키와 요금제 확인이 필요하며 플랫폼별 결과 범위는 실제 평가해야 한다. 이번 변경에서 가입·결제하거나 연동을 활성화하지 않았다.
- 더우인: 공식 영상 검색 API의 접근 권한 신청과 계정 적격 여부를 확인해야 한다. 일반 웹 로그인만으로 이 API 권한이 생기지 않는다. 해당 권한 없이 완전 자동 수집이 가능하다고 약속하지 않는다.
- Google Custom Search JSON API는 신규 고객 사용이 중단되었고 기존 고객도 2027-01-01까지 전환하도록 안내하므로 신규 장기 대안으로 채택하지 않는다.

## 공개 검색 HTTP 응답 검사 (2026-10-08)

실제 DuckDuckGo 검색 응답은 HTTP 202와 `challenge-form` 인증 화면이었지만,
기존 HTML 파서가 이를 `no_results`로 처리하고 나머지 검색어를 계속 요청했다.
공개 색인 검색에도 인증·429 검사를 적용한다. 인증 응답은 `captcha`와 실제 HTTP
코드로 기록하고 남은 검색을 중지한다. 이후 호출은 `verification_required`로 건너뛰며
새 요청·새 실패로 세지 않는다. 429는 5분의 제한된 휴식으로 처리한다.
응답 본문·쿠키는 접근 상태 기록에 저장하지 않는다. 다른 정상 공급자의 수집은 계속한다.
`request_manual_recheck`는 사용자의 명시적 인증 확인 후에만 호출하고, 다음 검색에서
인증 화면이 다시 나오면 즉시 문을 닫는다. 시간이 지났다는 이유로 인증을 해제하지 않는다.

## 근거

- [Google 비정상 트래픽 안내](https://support.google.com/websearch/answer/86640?hl=en): 자동 쿼리, 공유 네트워크, VPN/통신사 요인을 설명한다.
- [MediaCrawler #266](https://github.com/NanmiCoder/MediaCrawler/issues/266): 2024-05-15 유지관리자의 더우인·샤오홍슈 로그인 후 추가 인증 보고. 과거 사례이며 현재 모든 계정에 대한 증거는 아니다. 저장 쿠키만으로 추가 인증이 없어지는 것은 아님을 보여준다.
- [Playwright 영속 컨텍스트](https://playwright.dev/python/docs/api/class-browsertype#browser-type-launch-persistent-context): 전용 user_data_dir의 쿠키·저장 상태 재사용.
- [Cloud Vision Web Detection](https://docs.cloud.google.com/vision/docs/detecting-web)
- [Brave Video Search API](https://api-dashboard.search.brave.com/api-reference/videos/video_search/get)
- [더우인 공식 영상 검색 API](https://developer.open-douyin.com/docs/resource/zh-CN/dop/develop/openapi/douyin-search-capability/aweme-dy-video-search): `aweme.dy.video_search` scope와 별도 검색 권한, client token이 필요하다.
- [Custom Search JSON API 현황](https://developers.google.com/custom-search/v1/overview)
## 검색 대기 종료 시점의 인증 화면

동적 페이지는 마지막 로딩 확인 뒤에도 CAPTCHA를 표시할 수 있다. 결과 또는 대기
종료를 반환하기 직전에 인증 화면을 다시 확인하고, 결과가 없는 경우 저장한 실제
화면 본문에도 CAPTCHA 문구가 있으면 `captcha`로 기록한다. 이 경우 판독 실패나
검색 결과 없음으로 기록하거나 다음 검색어를 실행하지 않는다. 기존 인증 차단과
명시적인 사용자 인증 확인 요구는 그대로 유지한다.
