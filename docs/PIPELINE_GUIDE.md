# 네 프로젝트 연결 사용 안내

## 역할과 완료 범위

insta_auto는 후보 선정·원본 자료 확보, PersonalProject1은 대본 재가공,
VoiceBench는 음성 합성, auto_capcut은 컷·자막·효과를 담당한다.
현재 완료 상태는 `draft_ready`(CapCut 초안)이다. MP4 내보내기·게시 자동화는 포함하지 않는다.

## 실행 위치

| 프로그램 | 기본 주소 | 실행 |
|---|---|---|
| insta_auto | http://127.0.0.1:8775 | 해당 폴더에서 `.venv\Scripts\python.exe -m hotpost serve` |
| PersonalProject1 | http://127.0.0.1:18765 | 해당 폴더의 `start.cmd` |
| VoiceBench | http://127.0.0.1:8765 | 기존 Voice 시작 방식 사용; 외부 API 키가 로드되어야 함 |
| auto_capcut | HTTP 서버 없음 | 제작 요청이 독립 Python 작업 프로세스를 실행 |

insta_auto의 `HOTPOST_STUDIO_URL`, `HOTPOST_STUDIO_API_KEY_FILE`,
`HOTPOST_VOICEBENCH_URL`, `HOTPOST_VOICEBENCH_API_KEY_FILE`,
`HOTPOST_AUTO_CAPCUT_ROOT`, `HOTPOST_AUTO_CAPCUT_PYTHON`으로 배포 위치를 변경할 수 있다.
기본 VoiceBench 폴더명은 `Voice`이다. 키 내용은 설정 문서에 복사하지 않는다.
insta_auto의 전용 환경은 `requirements.txt`, auto_capcut은 자기 `requirements.txt`로 설치한다.
모델·FFmpeg·CapCut 및 로그인 세션은 별도 런타임 전제다.

## 제작 순서

1. 수집 대시보드에서 같은 릴스의 소스 영상 확보와 음성 대본 추출을 완료한다.
2. **릴스 제작 작업실**에서 두 작업과 정확한 상품명을 선택해 새 제작을 등록한다.
3. **재가공 요청**을 누른다. 참고 영상·원본 발화만 PersonalProject1에 전달한다.
4. 3안의 표현·관점·전개와 출처를 확인한다. 수정은 PersonalProject1에서 수행한다.
5. 새 관점·전개 변경·화면 변경 계획을 기록하고 편집 스타일을 선택한다.
6. 사용할 소스, 대사 핵심 단어가 포함된 장면 설명, 필요하면 시작·종료 초를 입력한다.
7. 대본과 계획을 확정한다. 이 시점의 텍스트와 해시를 보존한다.
8. CapCut을 종료한 상태에서 **음성·CapCut 초안 제작**을 실행한다.
9. 생성 음성을 듣고 초안을 열어 원본과 비교한다. 경고와 대사-장면 연결을 확인하고 최종 수정·내보내기를 한다.

대본이 바뀌면 다시 선택하여 새 버전을 만든다. 기존 음성을 다른 대본의 자막에 사용하지 않는다.
기존 버전의 대본·WAV와 편집 작업 파일은 보존된다. 작업 기록은
`insta_auto/data/productions/<id>/production.json`에 저장된다.

## 원본과의 차이 검사

PersonalProject1은 원본을 다른 관점·상황·설명 순서로 재작성하도록 지시하며,
생성 및 수동 수정 뒤에 문구 겹침과 말끝 규칙을 검사한다. 같은 문장에 문장부호만
바꾼 경우도 잡는다. 검사 실패·검사 해시 불일치는 통합 제작 선택을 막는다.

통과 상태는 “편집자 검토 필요”이며 창작상 차별성을 보장하지 않는다. 사용자는
원본과 새 대본·변환 계획을 비교하고, 결과 초안에서도 컷 구성과 실제 표현을 확인해야 한다.
스타일 선택은 실제 컷 속도·강조 색상 등에 적용한다. 새 프리셋은 실제 제작물로
품질을 조정해야 한다. 장면 구간 선택은 편집할
원본 구간을 제한하며, 장면 설명은 대사와 화면을 연결하는 키워드로 사용한다.
완전한 영상 의미 이해나 완성 MP4의 원본 대비 자동 판정은 아직 아니다.

## 재개와 중복 방지

- 재가공 요청은 제작 ID를 멱등 키로 사용한다. 서버가 중단돼도 다시 요청하면 같은 작업을 조회한다.
- VoiceBench 요청 ID는 제출 직후 저장한다. 재개는 해당 ID를 조회하며 새 TTS를 임의로 제출하지 않는다.
- 음성이 완료된 뒤 편집만 실패하면 기존 WAV를 재사용한다.
- 생성 완료 결과가 기록된 초안은 재개 시 재생성하지 않는다.
- 편집 프로세스가 초안 생성 후 결과 JSON 기록 전에 강제 종료된 극단적인 경우는 수동 확인이 필요하다.
- OS 파일 잠금으로 동일 제작의 동시 변경과 통합 경로의 무거운 단계 동시 실행을 막는다.
  각 앱에서 별도로 시작한 수동 GPU 작업까지 통제하는 전역 GPU 스케줄러는 아니다.
- 통합 PersonalProject1 작업은 완료 전에 자체 LLM을 내려 TTS 단계에 메모리를 양보한다.

## 매일 자료 확보

`python -m hotpost run --acquire`는 통계 수집 후 **조회수 / 팔로워 수**로
릴스만 선정하고 음성 대본·소스 자료까지 확보한다. 기존 평소 대비 급상승 지표는
모니터링에 유지하며 제작 후보 선정 기준과 구분한다.

초기 기본값은 팔로워 대비 1.8배 이상, 최소 1,000회, 한 번에 새 자료가 필요한 릴스
최대 5개다. 설정의 `acquisition_min_views_per_follower`, `acquisition_min_views`,
`acquisition_daily_limit`로 변경한다. 팔로워 미확인·조회수 누락·오래된 관측은 제외한다.
완료한 자료는 재사용하고 실패한 단계는 다음 실행에서 다시 시도한다.

Windows/macOS에서 `python -m hotpost schedule install`로 매일 7시 자료 확보 작업을
등록할 수 있다. 이번 구현 작업에서는 OS 예약을 설치하지 않았다.
Windows 예약은 한국 시간이며 사용자가 로그인한 세션에서 실행한다. PC가 꺼져 있거나
로그아웃 상태이면 정각 실행을 보장하지 않는다. macOS LaunchAgent는 시스템 현지 시간을 사용한다.
실행 상태 확인은 `python -m hotpost schedule status`, 제거는 `schedule uninstall`이다.

## 유지되는 한계

- 실제 촬영 원본과 자동 전사 정확도는 보장하지 않는다. 소스 출처·품질 메타데이터를 보존한다.
- 원본과 다르게 보이는 정도는 문구 검사와 스타일 변경만으로 확정할 수 없다.
- 생성한 CapCut 초안은 최종 MP4가 아니다. 내보내기 후 PersonalProject1 영상 검사 기능을 별도로 사용할 수 있다.
- 실제 계정·모델·CapCut을 사용하는 한 편의 운영 검증과 테스트용 서비스 연결 검증은 구분한다.
