# 게시물 상세와 제작실의 통합 자동 제작

## 확정 범위

- 매일 선정된 1·2위는 자동 제작. 다른 게시물은 상세의 자동 제작 시작 버튼으로 실행한다.
- 소스 확보 → 원본 발화 추출 → Top Pick 선정 → TTS → CapCut 프로젝트 → 실제 MP4 내보내기를 표시한다.
- 각 단계의 결과를 다운로드한다. 소스 개별 파일·출처 포함 ZIP, 원문 TXT, 제작 대본 TXT, WAV, 미디어를 포함한 프로젝트 ZIP, 최종 MP4를 제공한다.
- 길이는 선정 대본의 자연스러운 낭독에 맞춘다. 최종 출력은 1080×1920, 30fps MP4다.
- 배경음악 추가 및 관련 로직 변경은 이 작업의 범위에 포함하지 않는다.

## 하나의 작업, 보존되는 버전

`shortcode`마다 제작실 작업은 하나다. `runs`는 버전별 입력과 결과 참조를 저장한다. 게시물 상세와 제작실은 `/api/studio`를 함께 사용하며 별도 제작 큐를 만들지 않는다.

피드백은 `feedback`에 별도로 저장한다. 저장은 실행 중인 대본·음성·편집을 바꾸지 않는다. 재제작 버튼을 누르면 그 시점의 피드백을 `pending_reproduction`으로 고정한다. 실행 중인 단계가 있으면 결과를 저장한 뒤 새 버전으로 전환한다. 이후 작성한 피드백은 다음 요청을 위해 남긴다.

- 대본·발음·속도 변경: TTS부터 다시 생성.
- 소스 구성 변경: 편집부터 다시 생성.
- 장면·자막·강조 변경: 편집 수정부터 다시 생성.
- 모든 수정본은 프로젝트 등록과 최종 내보내기까지 이어진다.
- 대본과 장면 수정을 함께 요청하면 발화 유사도와 소스 해시로 구간을 연결한다. 대응이 모호하거나 선택한 소스가 제외됐으면 해당 단계에서 확인을 요청하며 임의로 다른 장면에 적용하지 않는다.

`latest_completed_run_id`는 실제 MP4 검증이 성공한 버전만 가리킨다. 새 버전을 만드는 동안 이전 완료본을 계속 다운로드할 수 있다. 수정본으로 전환된 미완료 버전도 확보된 결과를 보존한다.

## Top Pick

내장 집필기가 반환한 후보의 검토 상태·대본 해시·원문 해시 검증을 통과한 뒤 후보를 비교한다. 기존 자동 작업의 후보도 새 흐름으로 이어갈 때 재평가한다.

평가는 원본 발화와 실제 확보 소스 프레임을 근거로 수행한다. 도입부 30%, 근거 30%, 자연스러운 낭독 20%, 확보 장면 적합성 20%로 비교한다. 점수는 제작 적합성 평가이며 흥행 예측치가 아니다. 사실성 기준을 통과한 후보가 없으면 중단한다. 선택 이유와 후보 비교를 제작실에 표시한다.

## 복구와 대기

- 소스가 적어도 확보한 자료로 제작한다. 사용 가능한 소스가 0개면 자료 필요 상태로 남긴다.
- 일시적 연결 오류·시간 초과·429/502/503/504는 최초 시도 이후 최대 두 번 지연 재시도한다.
- 인증·검증·자료 부족 오류는 자동 재시도로 숨기지 않는다.
- CapCut이 열려 있으면 등록·내보내기를 대기한다. 종료 여부를 확인하여 이어가며 대기는 재시도 횟수를 소진하지 않는다.
- 내보낸 MP4의 존재·음성·길이·규격을 검증한다. 앱 종료 지연과 MP4 생성 성공을 구분한다.
- 작업과 버전은 SQLite에 저장하고 실행기는 별도 프로세스와 기존 OS 잠금을 유지한다.

## API

- `POST /api/studio`: `{shortcodes: [...], automatic: true}`
- `POST /api/studio/{id}/start-auto`: 기존 작업의 자동 진행 시작
- `save-script`, `select-candidate`, `apply-proposal`, `save-feedback`, `revise-edit`: 피드백 저장
- `reproduce`: 피드백을 고정하고 필요한 단계부터 재제작
- `discard-feedback`: 저장한 미반영 피드백 초기화
- `upload-source?name=...`: 원시 영상 바이트 업로드, 최대 512MB, 실제 영상 검사
- `download?run=...&asset=sources|transcript|script|voice|project|export`: 버전에 속한 완료 결과만 다운로드

피드백 저장은 `feedback_revision`으로 다른 화면의 수정 충돌을 감지한다. 일반 작업 상태의 revision은 자동 진행에 따라 계속 변경되므로 사용자 피드백 버전과 분리한다.

프로젝트 ZIP은 미디어를 함께 포함한다. 다른 PC에서 열 때는 CapCut에서 미디어 위치를 다시 연결해야 할 수 있다.
# CapCut이 열린 상태의 자동 내보내기

자동 제작에서 장면·음성·자막 렌더링과 이동 가능한 CapCut 프로젝트 생성까지 끝났다면,
사용 중인 CapCut 창 때문에 최종 MP4를 기다리게 하지 않는다. 프로젝트 등록만 나중으로
남기고 검증된 타임라인을 웹 렌더링 경로로 내보낸다. 실제 등록하지 않은 프로젝트에
`draft_path`를 만들어 넣지 않으며, 열려 있는 앱이나 사용자 편집 내용은 변경하지 않는다.
명시적으로 CapCut에서 열기를 요청한 경우에는 기존 등록 절차를 따른다.
