# 게시물별 자동 쇼츠 제작

> 2026-10-07 갱신: 대본 규칙과 Codex 집필·장면 분석 연결은 insta_auto로 내재화했다. 아래 script_auto·Gemini·3안 생성 설명은 과거 기록이며 현재 동작은 [내장 집필 안내](writing.md)가 우선한다.

## 병렬 제작과 소스 기준 (2026-10-05)

- 원본 레퍼런스와 실제 발화를 확보한 뒤 두 작업 흐름을 병렬 실행한다. 소스 전용 worker는 추가 수집을, 제작 worker는 원본 기반 대본 → 개인 복제 TTS를 진행한다. 기존 단일 프로세스 worker 잠금과 SQLite 원자적 claim을 유지한다.
- 새 제작의 편집 시작 조건은 플랫폼 합산 **최소 10개 사용 가능 영상(그중 TikTok 최소 5개) + 검토된 핵심 기능 장면 + 현재 선택 대본과 일치하는 음성**이다. 다른 플랫폼 영상 10개가 있어도 TikTok이 5개보다 적으면 수집을 계속한다. 확보 목표와 이번 편집에 쓰는 개수는 별개이며 사용자가 제작실에서 제외한 소스를 몰래 다시 선택하지 않는다.
- 이 기준은 `source_policy.version=2`로 새 작업·새 제작 버전·새 수집에 저장한다. 이미 완성된 버전은 기존 기준과 결과물을 보존한다. 기본값보다 낮은 예전 설정 파일의 값으로 새 기준을 낮추지 않는다. 검색·요청 예산과 인증 중지 조건은 유지한다.
- 파일/원 URL/영상 프레임 중복을 제거한다. 적절한 요리·활용 맥락 장면도 포함하되 핵심 기능 증거로 대신하지 않는다. 문자·워터마크 영상은 실제 검토된 가림 영역이 준비된 경우 사용 가능 개수에 포함한다.
- 부족하면 다음 검색어·언어·플랫폼·검색 방법으로 자동 추가 수집한다. 확보 소스와 검색 이력을 DB에 저장하고 재시작 후 이어간다. 사용자에게 추가 영상 확보를 요구하지 않는다. 같은 작업을 중복 등록하지 않는다.
- 정상적인 검색 결과 부족은 다음 검색 라운드로 이어간다. 일시적 연결 오류는 최대 두 번 재시도한다. 인증·설정·잘못된 결과 파일 등 영구 오류는 같은 요청을 반복하지 않고 해당 소스 작업에만 기록한다. CAPTCHA/429를 우회하지 않는다. 사용자가 중지했거나 이전 날짜 소모 정책이 적용된 작업은 오류·재시작 뒤에도 중지 상태를 지킨다.
- 완료된 영상과 기존 목소리 선택은 보존한다. 새 자동 제작이 기존 공식 목소리 음성을 개인 복제 결과처럼 재사용하지 않으며 개인 음성 부족 시 다른 목소리로 대체하지 않는다.
- 게시물 상세의 네 단계, 결과 우선 배치와 제작실 구분은 [상세 화면 기준](studio_detail_design.md)을 따른다.

## 현재 대본·음성 정책 (2026-10-05)

- 2026-10-06 최종 후킹·본문 재작성 정책: 첫 후킹의 효과·소구점·궁금증·전개를 유지하되 첫 문장부터 본문까지 실제 표현을 바꾼다. 후킹 문장 복사, 어미·문장부호·숫자 교정·CTA 추가만으로 재작성했다고 보지 않는다. `script_auto/studio/benchmark_wording.py`가 복사 구간과 동일 후보를 진단하여 자동 수정에 연결하고 말투 수정 이후에도 한 번 확인한다. 최종 후킹 의미 평가에 `rephrased_hook`을 포함한다. Top Pick 정책 10은 해당 의견을 받아 재작성한 후보를 먼저 비교하며, 평가 실패 시에도 동일한 우선순위를 적용한다. 점수·내용 의견은 사용자 승인 대기나 제작 중단 조건이 아니다.
- 사용자가 위 규칙을 승인하고 실제 제작 시작을 요청했다. 이후 벤치마킹의 기본 규칙으로 유지한다. 승인한 대본으로 제작할 때는 저장된 수정안을 새 버전에 먼저 반영하고 그 정확한 문장을 음성·자막에 사용한다.
- 직접 시작·재제작·재개한 작업은 `manual_resume`으로 기록한다. 이전 날짜 자동 선정만 소모 처리하며, 직접 요청한 제작은 자정 이후에도 계속한다. 원래 감지일·선정일과 기존 완성본은 보존한다.

- 신규 Hotpost 대본은 `evidence_mode: benchmark`로 원본 레퍼런스 영상과 실제 발화를 사용한다. 원본의 훅·불편·핵심 기능·생활 이득·댓글 궁금증을 인용과 연결하고, 소스 B-roll의 물체 설명으로 주제를 바꾸지 않는다. 정확한 브랜드·모델명은 숨길 수 있다. 공식 상품 정보가 없다는 이유만으로 이 대본 단계를 차단하지 않는다.
- `hotpost/writing/RULES.md`가 규칙 소유자다. 분석 인용·댓글 키워드·원본 특징 연결·후킹/본문 문장 복사·말끝·원본에 없는 사연 추가·미확인 효과를 검사한다. 원본에 있는 친구 집 시식 등 경험담 설정과 1인칭 재작성은 허용한다. 이전 초안과 수정 근거를 보존하고 제한적으로 자동 수정한 뒤 생성 대본으로 진행한다. 원문을 새 대본인 것처럼 대체하지 않는다.
- 원본 화자의 효능·체험은 제조사 확인 사실이 아니다. 미상 재료와 작동 원리를 추론하지 않는다. 대본 사실성·관심 유지와 확보 편집 소스의 적합성을 따로 평가하고, 맥락 소스만 있는 경우 핵심 동작 영상 부족을 유지한다.
- 자동 TTS는 VoiceBench의 **개인 복제 기본 음성**만 사용한다. 준비 상태와 개인 음성 여부를 확인하고 `voice_id`를 생략한다. 참조 녹음·복제 엔진 부족 시 공식 여성 목소리 등으로 대체하지 않는다. 시작 스크립트도 공식 소희 준비 상태로 자동 제작의 준비 부족을 숨기지 않는다.
- 다른 목소리는 제작실에서 직접 선택한 수동 시험에만 사용한다. 해당 제작 버전에 선택 출처를 저장한다. 과거 자동 작업의 공식 목소리 설정·완료 요청을 개인 복제 음성으로 재사용하지 않는다. 기존 완성본은 보존한다.
- 원본 분석은 제작실 대본 영역과 저장 API의 `benchmark_analysis`에서 확인한다. 현재 PC의 개인 참조 파일과 선택된 ZONOS2 Q8 엔진이 없어 자동 TTS는 준비 필요 상태다. 정상 연결 상태는 실제 합성 준비 상태와 구분한다.

## 이전 실패한 대본 복구 (2026-10-01)

- Gemini 키가 없으면 현재 제작실의 편집 검토는 로컬 `script_auto` 서비스를 사용한다. 과거 키 오류만 보고 키 등록을 요구하지 않고 현재 작업 결과를 다시 조회한다. 외부 웹 근거는 `script_auto`의 실제 검색 결과를 사용한다.
- 상품 링크 없이 같은 상품을 재구성할 때는 `evidence_mode: reference`를 명시한다. script_auto가 원본 프레임에서 관찰한 형태·배치·구성품과 시점을 별도 근거로 남긴다. 원본의 가격·재질·성능 주장이나 자막을 검증된 사실로 승격하지 않으며, 이후 선택 소스와 대본의 일치 검사는 유지한다. 기본값 `research`는 기존 공개 자료 조사 방식이다.
- 상품을 바로잡아야 할 때는 `POST /api/studio/{task_id}/regenerate-script`에 `product`, 선택값 `product_url`, `instructions`를 전달한다. 최초 대본이 아직 없는 실패 작업용 API이며, 실행 중 작업이나 기존 대본·편집본이 있으면 거절한다. 기존 완성본 수정은 제작실의 버전 수정 흐름을 사용한다.
- 수정한 입력과 명시적인 새 생성은 새로운 요청 ID를 사용한다. 동일 요청 재시도는 기존 외부 작업을 조회하며, 이전 후보와 오류는 `rewrite_history`에 보관한다. 상품 링크가 있어도 출처 검증을 통과해야 한다.
- Top Pick은 현재 제작 버전에 선택된 영상만 검사한다. 실패 이유는 작업 오류와 별도 `.rejected.json`에 남기며, 거절된 검토를 승인 결과로 재사용하지 않는다.
- 현재 벤치마킹은 재작성 검사·해시를 보존하고 내용 의견을 자동 수정과 후보 선정에 사용한다. 공식 상품 정보 부족이나 낮은 평가 점수만으로 TTS·영상 제작을 멈추지 않는다. 빈 대본·버전 불일치·파일/서비스 오류는 별도의 기술 오류다.

## 현재 통합 제작 흐름 (2026-09-28)

신규 자동 작업은 게시물 상세와 제작실이 같은 작업·버전을 공유한다. 실제 CapCut MP4 내보내기까지 이어지며 피드백 저장과 재제작 실행을 분리한다. 단계별 다운로드, Top Pick 비교, 버전 보존 및 예외 처리의 현재 명세는 [통합 제작 흐름](production_workflow.md)을 참고한다. 아래 2026-09-26 기록은 이전 완료 경계를 설명한다.

## 현재 운영: 오늘 발견한 핫 영상 전체 → 제작실 → 영상 리뷰 (2026-10-07)

`studio_auto_top_enabled: true`가 현재 자동 제작 설정이다. 오전 7시 수집이 끝나면
한국 시간 오늘 처음 발견한 기준 통과 영상 **전체**를 급상승순으로 제작실에 등록한다.
최신 정확한 조회수 미확인은 경고로 남기고 제작 등록을 막지 않는다. 잠정 후보의
판정은 그대로 표시한다. 샘플 데이터와 일부 계정만 수집한 `--only` 실행은 제외한다.

체크박스나 중간 승인 없이 다음 단계를 수행한다.

1. 기존 다국어 제품 검색·유사도 검사로 소스 확보. 편집 가능한 clean-source/light-overlay 사용.
2. 실제 음성 전사와 기준 영상에 내부 공통 집필 규칙을 적용해 Codex로 대본을 작성.
3. 재작성 검사 상태와 원문·대본 해시가 일치하는 첫 후보 자동 선택.
4. 기존 VoiceBench 설정으로 음성 생성, 실제 WAV 검증.
5. 별도 `auto_capcut.studio_runner` 프로세스로 장면·자막 계획과 리뷰 MP4 생성.
6. CapCut 프로젝트 등록 후 같은 제작실 작업을 **초안 검토**로 전환.

리뷰 MP4는 편집 실행기가 생성한 미리보기이며 CapCut 앱에서 내보낸 최종 MP4와는
구분한다. CapCut 프로젝트도 함께 생성하고 등록한다. 앱이 실행 중이면 안전한 등록을
위해 확인 필요 상태로 남기고, 저장·종료 후 해당 단계만 재시도한다.

### 화면과 상태

- 대시보드 카드 → `studio.html?work=...` → `/api/studio`가 같은 작업을 참조한다.
- 선정 순위, 현재 단계·진행률, 단계 기록, 실패 이유, 소스·대본·음성·영상이 제작실에 표시된다.
- 자동 대본·음성 선택은 사람의 승인과 구분하며 최종 영상은 사용자 리뷰 전 상태다.
- 자동 진행 중지는 현재 단계 결과를 보존하고 후속 단계 연결을 멈춘다. 직접 대본을 수정해도 자동 진행을 멈춘다.
- 기존 수동 작업은 자동화로 덮어쓰지 않는다. 같은 게시물은 수집을 반복해도 중복 제작하지 않는다.
- SQLite 작업 큐, 서비스 요청 ID, 편집 실행 결과를 보존하여 재시작·재시도를 이어간다.
- 최신 `data/report.json`을 대시보드와 자동 선정의 공통 데이터로 사용한다.

### 실행 환경

`config.json`의 현재 포트는 대시보드 18765, `script_auto` API 18767,
VoiceBench 8765다. **18766은 script_auto 내부 모델 서버 포트**로 비워 둔다.
대본·음성 서비스가 꺼져 있으면 로컬 주소에 한해 각 프로젝트의 전용 가상환경과
실행 진입점으로 시작한다. 형제 프로젝트의 패키지를 직접 import하지 않는다.
첫 설치에는 script_auto의 `setup.ps1`과 모델 준비가 필요하다. 기존 API 키 파일을
사용하며 저장소나 화면에 노출하지 않는다. 장면 의미 분석은 기존 `GEMINI_API_KEY`를 사용한다.

수집 명령이 독립 작업자를 시작하므로 대시보드가 닫혀 있어도 제작을 진행한다.
작업자 OS 잠금으로 중복 소비를 막는다. PC가 켜져 있고 기존 7시 작업의 실행 조건이
충족되어야 수집이 시작된다. 외부 인증·검색·모델 오류는 제작실에서 실패 단계로 표시한다.

## 이전 제작 방식 및 검증 이력

아래는 2026-09-24에 사용한 레거시 제작기의 기록이다. 현재 신규 자동 제작은 위의
제작실 큐를 사용한다. 레거시 결과 조회·다운로드 경로는 `/api/legacy-productions`이며,
`/api/productions`는 별도 UUID 제작 API이므로 혼용하지 않는다.

`production_enabled: true`일 때 운영 리포트의 기준 통과 릴스·동영상마다
소스 수집 → 실제 음성 전사 → 두 대본 재작성/검토 → VoiceBench 음성 →
새 CapCut 프로젝트 두 개 → 네이티브 MP4 내보내기를 순차 실행한다.
현재 리포트의 잠정 후보도 포함한다. 잠정 후보를 성과 확인으로 바꾸지는 않는다.

## 결과와 복구

- `data/productions/<shortcode>/state.json`: 단계별 상태와 결과 경로.
- `scripts-v3/`: 근거 조사, 독립 검토 응답, 두 낭독 대본. 기존 대본은 보존한다.
- 카드: 소스 ZIP 개수, 전사 TXT, 버전별 재작성 대본과 최종 MP4 링크.
- 오류 후 카드의 **중단 단계부터 다시 시도**는 남아 있는 파일을 재사용한다.
- 새 대본, 편집 소스 또는 무료 내보내기 설정으로 전환하면 새 프로젝트 이름을 쓴다.
- 실제 파일이 없으면 완료 링크를 제공하지 않는다. 실패한 단계는 진행 중으로 표시하지 않는다.
- 같은 게시물을 반복 발견해도 실행 중 작업을 중복 생성하지 않는다.

`GET /api/productions`, `GET /api/productions/<shortcode>`,
`POST /api/productions/<shortcode>/retry`가 상태/재시도 API다.
다운로드는 `/api/productions/<shortcode>/download?asset=` 뒤에
`source`, `transcript`, `script1`, `script2`, `video1`, `video2`를 사용한다.

## 실행 조건

VoiceBench 외부 API가 실행 중이고 기존 API 키를 사용할 수 있어야 한다.
대본 재작성은 환경변수 `GEMINI_API_KEY`를 사용한다. 키는 결과물에 기록하지 않는다.
소스 다운로드에 필요한 플랫폼 인증이 만료되면 해당 단계는 실패할 수 있다.

CapCut 연동 계약 1.3의 `export_profile: free`는 실제 내보내기를 막았던
Pro 음량 정규화·애니메이션·효과를 제외한다. 기존 standard 설정은 유지된다.
9.5.0.4050 한국어 UI에서 프로젝트 검색, 출력 폴더 지정, 내보내기, 종료를 구현했다.
화면 배치와 프로젝트명이 맞지 않으면 중단한다. 사용자가 편집 중인 CapCut은 건드리지 않는다.
프로젝트 두 개를 먼저 등록한 뒤 CapCut을 실행하며, 다음 버전은 종료가 끝난 뒤 진행한다.

## 검증 결과 (2026-09-24)

운영 게시물 네 개에서 실제 CapCut 프로젝트와 네이티브 MP4를 각각 두 개씩 생성했다.
총 8개 MP4는 모두 1080×1920, 음성 포함이며 프로젝트 길이와 일치한다.
버전별 파일 해시와 프로젝트명이 서로 다르고, 카드의 다운로드 8개가 HTTP 200으로
동일한 파일을 반환한다. 최종 MP4를 다시 전사하여 각 재작성 대본과 비교했고,
8개 영상의 장면·자막을 표본 프레임으로 확인했다.

| 게시물 | 소스 ZIP 영상 수 | 실제 음성 전사 | 최종 MP4 |
|---|---:|---|---:|
| 백팩 | 5 | 완료 | 2 |
| 여권 파우치 | 2 | 완료 | 2 |
| 뮬 신발 | 1 | 완료 | 2 |
| 치킨 | 4 | 완료 | 2 |

소스 ZIP에는 품질 미분류 영상도 포함될 수 있다. 자동 편집은 clean-source 또는
light-overlay 중 편집 가능으로 검토된 영상만 사용한다. 원본에 이미 들어간 자막,
워터마크와 검은 여백은 일부 결과에 남아 있으며 제거·권리 확보를 보장하지 않는다.
네 게시물의 성과 판정은 여전히 잠정 후보다.

판정 기준을 실제 API로 강화했을 때 4개 → 0개, 기존 값 복원 후 4개로 돌아왔다.
브라우저에서 판정 패널의 펼침·닫힘, 소스/대본 완료 표시와 8개 다운로드 링크를 확인했다.
Python 전체 116개 테스트, JavaScript 구문 검사, CapCut 내보내기 관련 8개 테스트를 통과했다.
로컬 검증 기록은 data/production-completion-audit.json, data/final-production-audit.json,
data/criteria-live-audit.json에 있다. 이 파일들은 Git에 포함하지 않는다.

현재 제품 검색은 사전 기반이다. 여권 복대·뮬 신발·마늘간장 치킨을 추가하고
직접 언급한 주제가 Vision의 연예인·배경 사물 추측보다 우선하도록 수정했다.
재수집에서 파우치의 착용 시연 2개와 뮬 신발 관련 영상 1개를 확보했다.
이전에 유사도 검사에서 탈락한 다운로드는 재시도 캐시의 우선 후보로 넣지 않는다.
일반 제품군이나 다른 모델의 성능을 미확정 제품의 사양으로 사용하는 조사도 금지한다.


## 2026-10-06: 완성 영상에서 사용자 판단

사용자 확정: 벤치마킹 대본·자막의 내용 평가, 말투, 후킹 점수, 미확인 주장 의견은 제작 중단 조건이 아니다. SCRIPT_GUIDELINES.md의 원본 후킹 보존·소폭 재작성 규칙으로 작성하고 제한적으로 자동 수정한다. Top Pick은 순위 선정용이며 모든 후보의 점수가 낮거나 평가 서비스가 실패해도 생성된 대본을 선택한다. 의견은 기록에 남기고 완성 영상에서 사용자가 판단한다. 에이전트가 추가 내용 검토를 이유로 automation.active=False 또는 editorial_content_hold를 새로 설정하지 않는다. 사용자의 명시적 중지는 존중한다. 빈 대본·버전 불일치·파일/서비스 오류는 별도의 기술 오류다. 자동 TTS는 VoiceBench의 사용자 복제 목소리를 유지하며 자막은 선택 대본과 실제 낭독문에 맞춘다. 기존 완성본을 일괄 덮어쓰지 않는다.
