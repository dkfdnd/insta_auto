# 게시물별 자동 쇼츠 제작

## 현재 통합 제작 흐름 (2026-09-28)

신규 자동 작업은 게시물 상세와 제작실이 같은 작업·버전을 공유한다. 실제 CapCut MP4 내보내기까지 이어지며 피드백 저장과 재제작 실행을 분리한다. 단계별 다운로드, Top Pick 비교, 버전 보존 및 예외 처리의 현재 명세는 [통합 제작 흐름](production_workflow.md)을 참고한다. 아래 2026-09-26 기록은 이전 완료 경계를 설명한다.

## 현재 운영: 상위 2개 → 제작실 → 영상 리뷰 (2026-09-26)

`studio_auto_top_enabled: true`가 현재 자동 제작 설정이다. 오전 7시 수집이 끝나면
최근 14일의 기준 통과 영상 중 **기본 급상승순 1·2위**를 고정해 제작실에 등록한다.
최신 정확한 조회수가 없는 순위는 건너뛰며 3·4위로 대체하지 않는다. 잠정 후보의
판정은 그대로 표시한다. 샘플 데이터와 일부 계정만 수집한 `--only` 실행은 제외한다.

체크박스나 중간 승인 없이 다음 단계를 수행한다.

1. 기존 다국어 제품 검색·유사도 검사로 소스 확보. 편집 가능한 clean-source/light-overlay 사용.
2. 실제 음성 전사와 기준 영상을 별도 `script_auto` HTTP 서비스로 전달.
3. 재작성 검사 상태와 원문·대본 해시가 일치하는 첫 후보 자동 선택.
4. 기존 VoiceBench 설정으로 음성 생성, 실제 WAV 검증.
5. 별도 `auto_capcut.studio_runner` 프로세스로 장면·자막 계획과 리뷰 MP4 생성.
6. CapCut 프로젝트 등록 후 같은 제작실 작업을 **초안 검토**로 전환.

리뷰 MP4는 편집 실행기가 생성한 미리보기이며 CapCut 앱에서 내보낸 최종 MP4와는
구분한다. CapCut 프로젝트도 함께 생성하고 등록한다. 앱이 실행 중이면 안전한 등록을
위해 확인 필요 상태로 남기고, 저장·종료 후 해당 단계만 재시도한다.

### 화면과 상태

- 대시보드 카드 → `studio.html?work=...` → `/api/studio`가 같은 작업을 참조한다.
- 선정 순위, 현재 단계·진행률, 단계 기록, 실패 이유, 소스·대본·음성·영상이 제작실에 표시된다.
- 자동 대본·음성 선택은 사람의 승인과 구분하며 최종 영상은 사용자 리뷰 전 상태다.
- 자동 진행 중지는 현재 단계 결과를 보존하고 후속 단계 연결을 멈춘다. 직접 대본을 수정해도 자동 진행을 멈춘다.
- 기존 수동 작업은 자동화로 덮어쓰지 않는다. 같은 게시물은 수집을 반복해도 중복 제작하지 않는다.
- SQLite 작업 큐, 서비스 요청 ID, 편집 실행 결과를 보존하여 재시작·재시도를 이어간다.
- 최신 `data/report.json`을 대시보드와 자동 선정의 공통 데이터로 사용한다.

### 실행 환경

`config.json`의 현재 포트는 대시보드 18765, `script_auto` API 18767,
VoiceBench 8765다. **18766은 script_auto 내부 모델 서버 포트**로 비워 둔다.
대본·음성 서비스가 꺼져 있으면 로컬 주소에 한해 각 프로젝트의 전용 가상환경과
실행 진입점으로 시작한다. 형제 프로젝트의 패키지를 직접 import하지 않는다.
첫 설치에는 script_auto의 `setup.ps1`과 모델 준비가 필요하다. 기존 API 키 파일을
사용하며 저장소나 화면에 노출하지 않는다. 장면 의미 분석은 기존 `GEMINI_API_KEY`를 사용한다.

수집 명령이 독립 작업자를 시작하므로 대시보드가 닫혀 있어도 제작을 진행한다.
작업자 OS 잠금으로 중복 소비를 막는다. PC가 켜져 있고 기존 7시 작업의 실행 조건이
충족되어야 수집이 시작된다. 외부 인증·검색·모델 오류는 제작실에서 실패 단계로 표시한다.

## 이전 제작 방식 및 검증 이력

아래는 2026-09-24에 사용한 레거시 제작기의 기록이다. 현재 신규 자동 제작은 위의
제작실 큐를 사용한다. 레거시 결과 조회·다운로드 경로는 `/api/legacy-productions`이며,
`/api/productions`는 별도 UUID 제작 API이므로 혼용하지 않는다.

`production_enabled: true`일 때 운영 리포트의 기준 통과 릴스·동영상마다
소스 수집 → 실제 음성 전사 → 두 대본 재작성/검토 → VoiceBench 음성 →
새 CapCut 프로젝트 두 개 → 네이티브 MP4 내보내기를 순차 실행한다.
현재 리포트의 잠정 후보도 포함한다. 잠정 후보를 성과 확인으로 바꾸지는 않는다.

## 결과와 복구

- `data/productions/<shortcode>/state.json`: 단계별 상태와 결과 경로.
- `scripts-v3/`: 근거 조사, 독립 검토 응답, 두 낭독 대본. 기존 대본은 보존한다.
- 카드: 소스 ZIP 개수, 전사 TXT, 버전별 재작성 대본과 최종 MP4 링크.
- 오류 후 카드의 **중단 단계부터 다시 시도**는 남아 있는 파일을 재사용한다.
- 새 대본, 편집 소스 또는 무료 내보내기 설정으로 전환하면 새 프로젝트 이름을 쓴다.
- 실제 파일이 없으면 완료 링크를 제공하지 않는다. 실패한 단계는 진행 중으로 표시하지 않는다.
- 같은 게시물을 반복 발견해도 실행 중 작업을 중복 생성하지 않는다.

`GET /api/productions`, `GET /api/productions/<shortcode>`,
`POST /api/productions/<shortcode>/retry`가 상태/재시도 API다.
다운로드는 `/api/productions/<shortcode>/download?asset=` 뒤에
`source`, `transcript`, `script1`, `script2`, `video1`, `video2`를 사용한다.

## 실행 조건

VoiceBench 외부 API가 실행 중이고 기존 API 키를 사용할 수 있어야 한다.
대본 재작성은 환경변수 `GEMINI_API_KEY`를 사용한다. 키는 결과물에 기록하지 않는다.
소스 다운로드에 필요한 플랫폼 인증이 만료되면 해당 단계는 실패할 수 있다.

CapCut 연동 계약 1.3의 `export_profile: free`는 실제 내보내기를 막았던
Pro 음량 정규화·애니메이션·효과를 제외한다. 기존 standard 설정은 유지된다.
9.5.0.4050 한국어 UI에서 프로젝트 검색, 출력 폴더 지정, 내보내기, 종료를 구현했다.
화면 배치와 프로젝트명이 맞지 않으면 중단한다. 사용자가 편집 중인 CapCut은 건드리지 않는다.
프로젝트 두 개를 먼저 등록한 뒤 CapCut을 실행하며, 다음 버전은 종료가 끝난 뒤 진행한다.

## 검증 결과 (2026-09-24)

운영 게시물 네 개에서 실제 CapCut 프로젝트와 네이티브 MP4를 각각 두 개씩 생성했다.
총 8개 MP4는 모두 1080×1920, 음성 포함이며 프로젝트 길이와 일치한다.
버전별 파일 해시와 프로젝트명이 서로 다르고, 카드의 다운로드 8개가 HTTP 200으로
동일한 파일을 반환한다. 최종 MP4를 다시 전사하여 각 재작성 대본과 비교했고,
8개 영상의 장면·자막을 표본 프레임으로 확인했다.

| 게시물 | 소스 ZIP 영상 수 | 실제 음성 전사 | 최종 MP4 |
|---|---:|---|---:|
| 백팩 | 5 | 완료 | 2 |
| 여권 파우치 | 2 | 완료 | 2 |
| 뮬 신발 | 1 | 완료 | 2 |
| 치킨 | 4 | 완료 | 2 |

소스 ZIP에는 품질 미분류 영상도 포함될 수 있다. 자동 편집은 clean-source 또는
light-overlay 중 편집 가능으로 검토된 영상만 사용한다. 원본에 이미 들어간 자막,
워터마크와 검은 여백은 일부 결과에 남아 있으며 제거·권리 확보를 보장하지 않는다.
네 게시물의 성과 판정은 여전히 잠정 후보다.

판정 기준을 실제 API로 강화했을 때 4개 → 0개, 기존 값 복원 후 4개로 돌아왔다.
브라우저에서 판정 패널의 펼침·닫힘, 소스/대본 완료 표시와 8개 다운로드 링크를 확인했다.
Python 전체 116개 테스트, JavaScript 구문 검사, CapCut 내보내기 관련 8개 테스트를 통과했다.
로컬 검증 기록은 data/production-completion-audit.json, data/final-production-audit.json,
data/criteria-live-audit.json에 있다. 이 파일들은 Git에 포함하지 않는다.

현재 제품 검색은 사전 기반이다. 여권 복대·뮬 신발·마늘간장 치킨을 추가하고
직접 언급한 주제가 Vision의 연예인·배경 사물 추측보다 우선하도록 수정했다.
재수집에서 파우치의 착용 시연 2개와 뮬 신발 관련 영상 1개를 확보했다.
이전에 유사도 검사에서 탈락한 다운로드는 재시도 캐시의 우선 후보로 넣지 않는다.
일반 제품군이나 다른 모델의 성능을 미확정 제품의 사양으로 사용하는 조사도 금지한다.
