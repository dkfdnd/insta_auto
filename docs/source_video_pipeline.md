# 소스 영상 탐색 파이프라인

> 2026-10-07 갱신: 대본 규칙과 Codex 집필·장면 분석 연결은 insta_auto로 내재화했다. 아래 script_auto·Gemini·3안 생성 설명은 과거 기록이며 현재 동작은 [내장 집필 안내](writing.md)가 우선한다.

## 목표와 경계

완성 릴스와 반드시 같은 원본을 찾는다고 보장하지 않는다. 릴스의 장면·제품과 유사하면서
재가공하기 좋은 **후보**를 찾고, 원 URL·권리 상태를 `manifest.json`에 남긴다.
다운로드 가능하다는 사실은 상업적 이용 허가가 아니다. 로그인·CAPTCHA는 사용자가
전용 브라우저에서 처리하며 DRM 또는 봇 차단을 우회하지 않는다.

## 반복 검색의 이력과 중지 기준 (2026-10-07)

빈 검색어가 발생하던 원인은 검색 이력을 플랫폼 구분 없이 제거하고, 다섯 묶음의
추가 의도를 회차 번호로 순환하면서 해당 묶음이 소진되면 빈 계획을 그대로 실행한 것이다.
현재는 근거 있는 검색어 풀을 유지하고 공급자별로 미사용 검색어를 고른다. 언어·행동·
클로즈업·준비·소분 등 유한한 의도를 전환하며, 요리에는 제품 언박싱을 붙이지 않는다.
텍스트 검색 경로가 소진되면 `query_exhausted`, 근거/지원 언어가 없으면
`no_supported_queries`로 기록한다. 빈 문자열을 텍스트 검색 요청으로 보내지 않는다.

`source_search/planner.py`는 회차 번호의 접미사 순환 대신 이전 결과로 다음 목적을 고른다.
첫 검색은 관찰한 핵심 행동을 우선하며, 검증 탈락은 원본·무자막 조건 또는 다른 클로즈업으로,
다운로드 실패는 다른 수신 플랫폼으로 전환한다. 전 회차에 후보가 전혀 없거나 요청이 모두
실패한 경로는 다음 회차에서 제외한다. 회차 안 추가 탐색도 조건을 바꾸며 사용 이력을 공유한다.
모델이 행동을 놓쳐도 캡션·음성·화면에 명시된 보관·냉장·소분·숟가락 동작을 사전 번역으로
검색한다. 언급 없는 냉장·재료·제품 기능은 만들지 않는다. 요리·보수 작업은 판매처 영상 검색을
제외한다. `search_strategy`에 목적·이전 실패 수·경로·제외 이유를 기록하며 화면에도 표시한다.

동일 공급자와 정규화된 동일 검색어의 실제 시도는 자동으로 반복하지 않는다.
확인 가능한 동의어·행동 분류도 공유 키로 비교하므로 `preparation process`와
`hands on preparation` 등의 말 바꾸기는 재시도로 쓰지 않는다. 무자막·클로즈업 등 영상 조건,
검색 언어 및 검색 대상 범위는 보존한다. 미등록 표현은 정확한 문자열 비교를 유지하며,
모든 임의의 문장을 의미적으로 동일 판정한다고 보장하지 않는다.
공급자가 달라지거나 공개 TikTok 색인처럼 검색 범위가 달라지면 별도 조건이다.
Google Lens·Yandex·선택적 Vision API는 이미지 SHA-256과 작은 색상 표본·dHash로
동일 파일 및 재압축·미세 변화한 유사 장면을 제외한 뒤 대표 이미지를 고른다.
색상 거리까지 확인해 해시만 같은 서로 다른 단색 장면을 잘못 합치지 않는다.
기존 이름 기반 이력도 존중하며, 보존된 기준 프레임에서 과거 유사도 표본을 한 번 복원한다.
최근 500개만 보관하던 사용 이력을 영속 검색 키로 변경했고, 업데이트 전 완료 회차의
manifest에서 이력을 한 번 복원한다. 브라우저 요청은 탐색·업로드 직전에 체크포인트를 저장해
프로세스 종료가 실제 시도를 미시도 기록으로 바꾸지 않도록 한다.

자동 수집은 기본 연속 3회 무성과(`source_no_progress_rounds`), 총 12회
(`source_collection_max_rounds`), 실제 검색·다운로드·검증 실행 누적 3600초(`source_collection_time_budget`) 이후
새 회차를 시작하지 않는다. 실행 중인 회차는 자체 예산 안에서 결과를 보존한 뒤 평가한다.
큐 대기와 회차 사이 휴식은 실행 누적 시간에 포함하지 않는다. 실제 실행 시간은
`source_acquisition.execution_seconds`에 저장하며 실패한 실행의 시간도 합산한다.
성과는 목표까지의 제작 가능 수량·필수 플랫폼 수량·검증된 핵심 장면의 개선이다.
검색/후보 수만 늘거나 목표를 넘긴 보조 영상 수만 늘어나는 것은 성과가 아니다.
실행할 검색 조건이 모두 없으면 즉시 중지한다. 인증·로그인·검색어/이미지 소진·
다운로드/검증/중복 사유를 `source_acquisition.hold`와 제작실에 표시한다.
중지는 서버 재시작 후에도 유지하고 대본·음성·기존 소스는 보존한다.
명시적 자동 재개나 새 조건 추가 검색은 예산을 새로 시작하지만 기존 검색 이력과
획득 영상을 지우지 않는다. 인증 차단 해제는 기존 수동 확인 경로를 따른다.

## 현재 처리 순서

같은 레퍼런스에서 이미 확보한 소스와 미검증으로 남은 후보를 먼저 다시 검증한다.
`source_search/library.py`는 다른 레퍼런스용으로 보관한 실제 파일도 제품명·다국어
동의어·후보 자체의 관찰 행동으로 찾아 미검증 후보로 제안한다. 이전 선택·기능 승인·
블러 승인은 승계하지 않으며, 현재 레퍼런스 기준으로 모두 다시 검사한다.
현재 묶음에서 검사한 URL은 다시 제안하지 않고, 사용자 설정으로 제외한 플랫폼과
원본 레퍼런스 파일·저장 경로 밖의 파일은 후보에서 제외한다.
`acquisition=local-cache`, `reused_from`은 보관 파일 재사용 근거이며 외부 다운로드
시도에 포함하지 않는다. `platform_outcomes.local_reuses`와 `network_received`로
재사용과 새 수신을 구분한다. 과거 기록에 이 필드가 없으면 새 다운로드로 추정하지 않는다.
실제 파일이 없는 과거 기록과 이미 검사한 URL은 제외하고, 부족분은 새 외부 검색으로
보충한다. 저장 소스도 현재 레퍼런스의 기능·장면·중복·블러 기준을 통과해야 사용한다.
기존 원본 레퍼런스 영상이나 전사문을 새 수집의 분석 자료로 다시 쓰는 것은 별도의
초기화 캐시 규칙으로 제한한다.

자동 제작은 아래 탐색을 한 번으로 끝내지 않고 `studio_sources.py`의 저장 가능한 수집 라운드로 이어간다. 새 제작·수집 목표는 플랫폼 합산 사용 가능 영상 최소 10개이며, 이 중 TikTok 최소 5개와 검토된 핵심 장면이 필요하다. 다른 플랫폼의 수량으로 TikTok 부족분을 대체하지 않는다. 소스 확보와 원본 기반 대본·개인 복제 음성은 병렬 진행하며 편집은 목표 확보 후 시작한다. 사용자 수동 선택과 과거 완성본은 보존한다. 서버 오류의 동일 요청 무한 재시도와 정상적인 검색 전략 전환은 구분한다.

자동 수집의 장면 검토는 실제 검토를 마친 소스만으로 위 목표가 충족되면 종료하고 다음 제작 단계로 넘긴다. 미검토 후보는 사용 가능 수에 넣지 않는다. 추가 다운로드와 원본 manifest는 그대로 보존하여 이후 검색·재검토 후보로 사용하고, 라운드의 `review_completion`에 검토 수·미검토 수·달성 근거를 저장한다. 사용자 수동 수집·명시적 새로고침은 요청된 후보 전체의 검토를 유지한다.

1. `data/hotpost.db`의 릴스 메타데이터를 읽고, 같은 shortcode의 정상적인 저장 영상이 있으면
   소스·대본 작업 폴더에서 재사용한다. 없으면 `collection_source=browser`에서는 로그인·수집과
   같은 전용 Chrome 프로필로 해당 게시물(`/p/<shortcode>/`)을 열고, shortcode가 일치하는
   응답의 영상만 받는다. 예전 세션 파일은 필요하지 않다. 다른 수집 방식에서는 기존 세션을 사용한다.
2. 실제 음성 전사를 확보하고 ffmpeg로 균등 프레임과 장면 전환 프레임을 합친다. 캡션, 음성 전사, 기준 프레임 OCR,
   선택적 Vision 라벨에서 제품·브랜드·특징·명시된 품번을 추출한다. 제품을 식별하지 못하면
   OpenCLIP 카탈로그로 보완한다. 제품/브랜드 제외/외형/상세 리뷰/시연/개봉 의도를
   영어·중국어·한국어로 확장하고 검색어마다 근거·언어·신뢰도를 남긴다.
3. 전용 Playwright Chrome 프로필에서 TikTok 영어·한국어·중국어 검색을 먼저 수행하고,
   Google Lens·Yandex 역이미지, Douyin·Xiaohongshu·Bilibili 검색을 이어간다.
   중국 플랫폼은 중국어 검색어만 허용하며 미사용 중국어 검색어가 없으면 건너뛴다.
   웹/Bing/YouTube 검색, 로컬 후보 캐시,
   선택적 Pexels 후보도 합친다. 전용 브라우저 쿠키가 있으면 `yt-dlp`와 공유한다.
   각 검색·재시도 전 기본 30초 간격(`source_browser_search_interval`)을 둔다.
   CAPTCHA는 진행 화면에 수동 인증 대기를 표시하며, 미해결 CAPTCHA 또는 HTTP 429 뒤에는
   해당 공급자를 기본 최대 10분(`source_browser_block_cooldown`) 쉬게 한다. 휴식 상태는 로컬 파일에
   저장하여 검색 프로세스가 바뀌어도 유지한다. 전체 검색 시간 제한은 그대로 적용하므로
   느린 검색에서는 완료된 검색 수가 줄어들 수 있다. 이 간격이 CAPTCHA 방지를 보장하지는 않는다.
   Bing·DuckDuckGo·YouTube·Vision·Pexels 요청, 영상/썸네일 다운로드, Instagram 상세 탐색·스크롤에는
   `request_pacing.py`의 1~3초 무작위 대기를 추가한다. yt-dlp 내부 메타데이터 요청은 최소 1초,
   다운로드 전 1~3초, 내부 재시도는 2초 대기를 사용한다. 이미 저장된 파일과 로컬 연산에는 대기하지 않는다.
4. 영상 상세 URL을 검증하고 중복 URL을 제거한다. 초기 최대 40개 후보를 플랫폼별로 배분한다.
   다운로드 실패는 성공 검사 한도를 소모하지 않는다. 기본 성공 다운로드 30개, 총 시도 60회,
   다운로드/검증 단계 900초의 예산을 적용한다. 진행 중인 한 건의 검증은 예산을 넘겨 완료할 수 있다.
   유효 소스가 목표보다 적으면 미사용 검색어와 검증된 후보 제목으로 한 번 추가 검색해 최대 12개를 보완한다.
   장면 점수는 dHash 55% + OpenCLIP 45%다. 기본 functional 모드는 색·일부 디자인 차이를
   허용하며 핵심 기능이 실제 영상 프레임에서 같다고 검토된 후보를 보존한다. 단순한 제품군·제목
   일치만으로 채택하지 않는다. 경계 후보는 작업당 최대 3개를 script_auto 영상 검토로 확인하고
   관찰 행동·차이점·프레임·파일 해시를 functional_review에 남긴다. product 모드는 의미 유사도 0.82 이상인
   대체영상도 보존한다. scene 모드는 기존 장면·제품 복합 게이트를 사용한다.
5. 후보 프레임의 자막·워터마크를 Tesseract 또는 저장된 EasyOCR ko+en 모델로 검사해 `clean-source`, `light-overlay`,
   `edited-with-text`, `unknown`으로 구분한다. 재가공 적합도(`source_score`)는
   깨끗한 화면 55% + 제품 의미 유사도 30% + 장면 dHash 15%다.
6. 관련성·길이·해상도·자막 게이트와 파일/장면 중복 검사를 통과한 후보 중 기본 상위 20개를 ZIP에 넣는다.
   `clean_sources/`, `review_needed/`, `unclassified/` 폴더로 유형을 구분한다.
   자막이 많은 `edited-with-text`도 소스 후보로 보존하며 `blur_required`를 표시한다. 최종 편집은
   실제 프레임에서 확인한 `watermark_masks` 영역이 있어야 진행한다. CapCut의 흐리게 효과와
   직사각형 효과 파일을 확인하고 네이티브 편집 가능한 효과를 넣는다. 미리보기도 같은 영역을 가린다.
   효과 파일이나 검토 영역이 없으면 완료 처리하지 않는다. 같은 제품의 다른 촬영을 보존하기 위해
   의미 임베딩 유사도만으로 재업로드 중복이라고 판정하지 않는다.
   ZIP에는 미리보기·`manifest.json`이 있지만 분석용 기준 Instagram 릴스는 없다.

## 결과 해석

TikTok 검색은 HTTP 200이나 쿠키 존재만으로 성공 처리하지 않는다.
검색 화면의 초기 3초 뒤에도 결과가 없으면 같은 페이지에서 최대 15초 더
기다리며 결과·명시적 빈 결과·인증 차단을 구분한다. 새 검색 요청은 보내지 않는다.
영상 주소는 페이지가 이미 받은 `/api/search/item/full/` 또는
`/api/search/general/full/` 응답 중 검색어가 일치하는 실제 video 항목에서만 읽는다.
문서 전체의 알림·활동·추천 영상 주소와 사용자 항목은 검색 후보로 세지 않는다.
결과가 확인되지 않으면 `page_unresolved`이며 `no_results`와 다르다.
`result_wait_seconds`와 `result_method`를 남긴다. 검색 후보 수·다운로드 성공 수·
핵심 기능이 검토된 제작 가능 소스 수는 서로 별도로 보고한다.

페이지 판독 실패는 인증 실패와 별도로 `search_readiness/<platform>.json`에 보존한다.
같은 판독기 버전에서는 검색어만 바꾸어 다시 방문하지 않는다. 판독기 수정 또는 사용자의
명시적인 세션 저장 후 한 번 재확인하며, 다시 판독에 실패하면 경로를 중지한다.
시간 경과만으로 중지를 해제하지 않는다. 별도의 CAPTCHA·로그인 차단도 계속 적용한다.

후보 제목의 주제·핵심 행동 일치는 검사 순서를 정하는 근거다. 제목만으로 제작 가능 판정을
내리지 않으며 제목이 없는 후보도 유지한다. 검색 결과에서 초 단위 길이가 확인된 후보는
기존 길이 기준을 먼저 검사한다. 길이를 모르면 다운로드 후 실제 파일을 확인한다.
후보별 다운로드·재시도에는 기본 최대 60초(`source_candidate_download_budget`)와 같은
플랫폼의 미검증 후보 수에 따른 시간 배분을 적용한다. 플랫폼·전체 남은 시간도 넘기지 않는다.
플랫폼 300초의 실제 사용량에는 다운로드 대기와 실패도 포함한다. 로컬 장면 검사는 별도이며
전체 검사 시간 한도는 유지한다. 예산 때문에 미검증한 URL은 다음 라운드에서 재검색 없이
먼저 이어받는다. 이미 다운로드 실패·검증 탈락·검사 완료한 후보는 이월하지 않는다.
검사 순서 근거·검색 결과의 길이·후보별 시간 배분·탈락 이유는 제작실의 검색 내역에 표시한다.

`similarity` 0.82 이상이며 dHash 0.80 이상일 때 `same-scene-likely`, 0.72 이상은 `close-match`다.
제품 모드에서 의미 유사도 0.82 이상이지만 dHash가 0.72 미만이면 `product-related`로 표시한다.
그 밖은 `topic-related`다. 점수는 확률이 아니며 임계값은 대표 데이터셋으로 보정할 필요가 있다.
모두 자동 추정이며 원본 일치나 사용 권리를 보장하지
않는다. `source_quality`도 OCR 보조 판정이라 제품 포장·현장 간판을 자막으로
오인할 수 있다. 저신뢰 텍스트가 반복되는 영상은 OCR 결과가 비어도 클린으로 단정하지 않는다.
EasyOCR ko+en은 중국어 등 다른 언어를 완전히 읽지 못한다. 최종 선택 전 영상과 원 출처·권리 상태를 확인한다.

직접 플랫폼 검색은 앞쪽 4개 문자열을 잘라 쓰지 않고 언어별 검색 계획을 사용한다. 기본 플랫폼당
검색어 6개, 후보 12개이며 TikTok은 기본 후보 15개(사용 가능 목표의 3배)를 확보하도록
배분한다. TikTok은 첫 세 검색을 영어·한국어·중국어에 배정하며 후보 상한에 도달해도
계획한 언어 검색을 생략하지 않는다. CAPTCHA·요청 제한·전체 시간 제한은 계속 우선한다.
`manifest.json`에는 제품 근거, 검색어 계획, 추가 검색 근거, 예산 중단 사유, 플랫폼별
발견/다운로드/선정 개수를 기록한다. 추가 검색은 직접 플랫폼·YouTube·Bing 경로로 한 차례 수행한다.

현재 제품 식별과 번역은 규칙·다국어 사전 및 기존 OpenCLIP 카탈로그, 텍스트 근거 기반 모델 확장을 사용한다.
임의의 제품 모델을 추론하는 범용 비전 언어 모델이나 전체 라이브러리의 벡터 검색은 구현하지 않았다.

설정 기본값은 `hotpost/config.py`, 실제 점수·ZIP 구현은 `hotpost/source_finder.py`,
브라우저 검색은 `hotpost/browser_search.py`, 텍스트 오버레이는
`hotpost/text_overlay.py`가 기준이다. 이 문서와 코드가 다르면 코드 구현을 확인하고
문서도 함께 갱신한다.

## 검색 개선 및 실행 기록 (2026-09-26)

- 신규 제작은 실제 음성 전사와 화면 OCR을 확보한 다음 소스 검색을 시작한다. 독립 소스 검색도 기존 전사가 없으면 분석을 먼저 시도한다. 음성과 화면 글자는 별도 근거로 유지하며, 실패 시 캡션·이미지 검색으로 진행하고 진단을 남긴다.
- 주제 사전은 요리와 보수 작업에 언박싱 대신 조리 과정·보수 과정 검색 의도를 적용한다. 설정된 모델(Gemini 또는 script_auto 로컬 모델)로 실제 캡션/음성/OCR의 인용 근거를 확인한 한국어·영어·중국어 검색어를 추가한다. 모델 검색어는 `model_inferred`이며 원본·제품 일치를 보증하지 않는다. 모델 미설정/실패는 사전과 이미지 검색으로 대체하고 명시한다.
- 언어별 검색어는 플랫폼에 맞게 배분한다. 중국 플랫폼에는 중국어를 우선한다. 후보 배분과 요청 제한은 YouTube/Bilibili를 각각 취급한다.
- `yt-dlp[default]`로 해당 버전과 호환되는 EJS 구성요소를 설치한다. `source_ytdlp_js_runtime` 또는 `HOTPOST_SOURCE_YTDLP_JS_RUNTIME`에 `node:실행파일절대경로`를 지정하면 예약 실행의 PATH 차이에도 같은 런타임을 사용한다. 미지정 시 PATH/가상환경의 Deno, Node를 찾는다. 공식 설치 안내: https://github.com/yt-dlp/yt-dlp/wiki/EJS
- Bilibili 다운로드는 90초 후 한 번만 150초 범위에서 이어받기를 시도하며 남은 전체 다운로드 시간 예산을 넘기지 않는다. 로그인·CAPTCHA·DRM 오류와 요청 제한은 기존 중단 원칙을 유지한다.
- 유효하고 중복되지 않은 소스가 `source_min_usable`(기본·최소 10)보다 적거나 TikTok이 최소 5개보다 적으면 라운드 내 한 차례 추가 검색한다. 플랫폼별로 아직 실행하지 않은 주제·행동 검색어와 검증 후보 제목의 근거를 사용한다. `source_refine_max_candidates`(12), 전체 시도 60회, 성공 다운로드 검사 30개, 다운로드/검사 예산 900초의 상한을 유지한다. 플랫폼별 기본 300초(`source_platform_probe_budget`)를 적용해 특정 플랫폼이 전체 예산을 소모하지 않게 한다. 추가 검색 자체의 대기 시간은 이 900초에 포함하지 않는다. 부족하면 영속 큐에서 다음 전략으로 보충하며 확보 전에는 편집 준비 완료로 표시하지 않는다.
- 180초 초과, 최대 `source_long_video_max_seconds`(1800) 영상은 8개 구간에서 각각 3프레임을 검사한다. 기능 일치 모드는 의미 유사도 0.60 이상, 제품/장면 일치 모드는 0.82 이상인 최선 구간을 `source_segment_seconds`(30)초로 추출한다. 이는 후보 구간 제안일 뿐이며 일반 기능·관련성·자막·해상도·중복 검사를 모두 다시 적용한다. 긴 영상의 색·디자인 차이가 구간 추출 전에 최종 탈락을 만들지 않도록 기능 검토와 같은 후보 기준을 사용한다. 전체 영상의 모든 장면을 검사하는 것은 아니다. 원본 URL, 원본 파일, 시작/끝 시점을 결과에 보존한다.
- 길이·해상도·화면 비율을 먼저 검사한다. 형식 기준을 통과할 수 없는 영상이나 긴 영상에서 유효 구간을 얻지 못한 경우에는 무거운 프레임·유사도·OCR 검사를 생략한다.
- `manifest.json`의 `query_details`는 검색 계획, `search_audit`는 실제 실행 기록이다. 공급자, 검색어, 언어, 결과 수, 오류·로그인 필요 등을 구분한다. 후보·다운로드·채택 개수와 탈락 사유는 제작실에서 조회할 수 있다. 이전 실행에 기록이 없으면 없다고 표시한다.
- 브라우저 검색은 별도 프로세스에서 수행하고 단계마다 중간 결과를 저장한다. 일반 검색은 `source_browser_timeout`(360초), 추가 검색은 최대 180초의 예산 내에서 쿠키 저장과 정상 종료 시간을 남긴다. 브라우저가 응답하지 않을 때만 해당 작업 프로세스를 제한 종료한다. 완료된 후보와 실행 기록을 회수하여 다운로드를 계속하며, 멈춘 사이트를 성공으로 기록하지 않는다. 로그인 쿠키와 사용자 파일은 삭제하지 않는다.
- TikTok 사용 가능 소스 목표는 `source_tiktok_min_usable`(기본·최소 5)다. 실제 파일이 있고 관련성·중복·편집 준비 검사를 통과해야 센다. 글자·워터마크 영상은 검토된 블러 마스크가 준비된 경우에만 포함한다. TikTok 후보를 먼저 검사하고 최종 선택에서도 목표 수만큼 자리를 확보한다. 다른 플랫폼에서 전체 목표를 달성해도 TikTok 목표가 부족하면 추가 검색을 시도한다. 품질 기준이나 요청·시간 제한을 풀어 개수를 맞추지 않는다. `platform_targets.tiktok`에 확보 수, 세 언어의 검색 완료 여부, 부족 사유를 기록한다. 언어별 검색 여부는 진단 정보이며, 실제 사용 가능 영상 5개 확보 여부와 구분한다.
- 검색어 확장은 내장 Codex 연결을 사용한다. script_auto 서비스나 로컬 집필 모델에 의존하지 않는다. 생성 실패 또는 검증 가능한 인용 근거가 없으면 사전 검색어만 사용하고 누락 언어를 기록한다. 번역이 준비되지 않은 언어를 검색했다고 표시하지 않는다.
- 플랫폼 검색은 Playwright로 Chrome을 제어하고, 영상 파일은 주로 yt-dlp로 받는다. 검색 완료 시 탭과 전용 Chrome을 닫으며 추가 검색은 새 프로세스로 시작한다. 검색 결과 썸네일은 로드하고 자동재생 미디어·폰트만 차단한다. 창이 닫힌 사실만으로 검색 성공을 판단하지 않고 실행 기록을 확인한다.
- 제작실의 **다국어 추가 수집**은 영속 큐의 `refresh_sources` 작업이다. 기존 대본·음성·편집본과 소스는 유지하며 신규 소스만 추가한다. 추가 소스는 다음 편집 실행부터 사용된다. 기존 편집본의 장면을 자동 교체하지 않는다.

## 플랫폼 로그인 버튼과 세션 재사용

TikTok·더우인·샤오홍슈·Google·YouTube 로그인은 `platform_login_profiles/<platform>`의 별도 Chrome 프로필에서 연다.
수집 프로필이나 검색 잠금을 기다리지 않으며, 로그인 중에도 자동 수집은 계속된다. Instagram은 기존 수집 프로필 계약을 유지한다.
로그인 창을 닫으면 활성 상태를 해제하고, 열린 플랫폼 버튼을 다시 누르면 해당 탭을 앞으로 가져온다.
사용자가 인증한 쿠키는 `platform_sessions/interactive`에 별도로 저장해 수집기의 오래된 쿠키와 분리한다.
새 로그인 버전은 다음 검색 시작 시 한 번 적용하고, 이후 검색 브라우저의 갱신된 쿠키를 보존한다.
다운로더는 로그인 쿠키의 작업별 비공개 사본을 사용한다. 창을 닫는 것만으로 CAPTCHA 차단을 해제하지 않는다.

설정 → 연결 → 플랫폼 로그인 관리에서 Google 검색 인증·더우인·샤오홍슈·TikTok·Instagram을 각각 열 수 있다.
해당 플랫폼만 열며, 로그인·인증 후 `세션 저장 완료`를 누르면 영속 Chrome 프로필과
플랫폼별 비공개 쿠키 파일을 보존한다. 소스 플랫폼 로그인은 검색과 분리된 프로필을, Instagram은
기존 수집용 프로필을 사용한다. 브라우저 재실행 시 만료되지 않은 쿠키만 복구하며,
새로운 사용자 로그인 버전이 있을 때만 검색 프로필의 기존 쿠키를 갱신한다. 쿠키 존재와 실제 인증 확인을 구분한다.
CAPTCHA와 로그인 요구는 시간이 지났다는 이유로 자동 해제하지 않는다. 사용자의 세션 저장 후
화면의 인증 요구가 사라진 경우 다음 검색을 다시 확인한다. 자동 수집 전체를 장기 휴식시키지 않고
다른 공급자로 진행한다. 근거와 운영 방향은 [검색 인증 반복 문제 점검](search_access_reliability.md)에 있다.
TikTok 후보는 사이트 검색과 공개 검색의 직접 영상 링크에서 먼저 확보한다. 최소 목표는 5개이며
관련성·화질·중복 기준이나 차단 중지 규칙을 완화해서 채우지 않는다.

## 수량 정책과 실패 근거 보존

`source_policy.py`가 새 수집의 전체 10개/TikTok 5개 기준을 버전 2로 만든다. 새 작업과 새 제작
버전에 복사하며, 기준이 없던 과거 완성 버전은 버전 1로 읽는다. 기존 결과물을 다시 수집하거나
미완료로 바꾸지 않는다. 이후 사용자가 새 제작·추가 수집을 시작하면 새 기준을 적용한다.
전체 수량은 URL 정규화, 파일 SHA 및 프레임 중복 검사를 거친 서로 다른 영상 수다.

`manifest.json`은 준비 시작과 후보 검사 중간에도 원자적으로 저장한다. `source_acquisition.rounds`
에는 라운드별 manifest 경로·정책·`platform_outcomes`를 남긴다. 원본 준비 단계에서 실패했다면
전역 실패로 기록하며 아직 방문하지 않은 TikTok에 CAPTCHA 실패를 만들어 붙이지 않는다.

`platform_outcomes`는 `search_attempts`, `download_attempts`, `skipped_searches`, `skipped_reasons`,
`search_evidence`를 구분한다. 저장된 인증 차단으로 건너뛴 항목은 새 요청·새 CAPTCHA가 아니다.
`not_attempted`, `no_candidates`, `captcha`, `auth_required`, `rate_limited`, `access_denied`,
`download_failed`, `quality_rejected`, `duplicate`, `budget_exhausted`를 근거에 따라 기록한다.
단순 HTTP 403은 로그인 실패로 단정하지 않는다. Bing 등의 `site:` 검색은 해당 플랫폼을 대상으로
한 검색엔진 채널로 기록하며, 플랫폼 내부 검색 방문으로 표시하지 않는다.

## 기존 파일 재검토와 사용 구간

예전 기능 판정에서 제외된 파일도 원본 SHA와 실제 프레임을 유지한 채 최신 판정으로 재검토할 수 있다.
외관 중심 상품은 제품을 보여주거나 착용하는 장면 자체가 검토 대상이다. 다른 색상·모델의 보조
장면은 정확한 색상·제품·성능의 증거로 사용하지 않는다. 명시적인 사용 제외 기록
(`manual_usage_review.editing_eligible=false`)은 이후 자동 기능 판정으로 해제하지 않는다.

삽입 문구가 있는 파일은 `source_mask_review.py`에서 실제 시간·파일 해시·1080×1920 화면에
연결된 프레임과 블러 영역을 검토한다. 문구가 없는 구간을 택할 경우에도 모든 표본을 직접
확인하고 `no_overlays_confirmed=true`를 기록한다. 빈 OCR 결과만으로 승인하지 않는다.
`reviewed_intervals`는 편집에 허용한 구간이며 전체 파일의 승인을 뜻하지 않는다. Auto CapCut의
장면 추출·캐시 재사용·렌더링은 이 구간 밖의 장면을 거부한다. 원본 파일과 원 URL은 보존한다.

자동 수집은 `source_overlay_review.py`로 이 검토를 수행한다. 파일 앞·중간·끝의 최대 4초
구간을 실제 캔버스와 시간으로 추출한다. 새 검증은 구간마다 시작·끝과 중간 세 시점의
총 다섯 프레임을 사용하여, 종전 세 표본 사이에 길어진 자막도 더 확인한다. 원본과 가림
미리보기는 좌표·해상도를 유지하고 JPEG 전송량만 줄여 호출 크기 제한을 지킨다.
첫 Codex 시각 호출이 영역을 제안하며 별도의
호출이 모든 표본·영역의 가림 범위와 제품 가시성을 검토한다. 승인된 구간만 편집에
포함하고 핵심 기능도 그 구간의 프레임으로 다시 확인한다. 불확실하거나 제품이 가려지는
구간은 사용하지 않는다. 기존 저장 파일에 이 검토만 누락된 경우 외부 검색 전에 검토하며,
그 과정은 새 검색 요청·실패·검색 회차로 세지 않는다. 동일 입력의 거절/실패를 무한 반복하지 않는다.

독립 검토에는 원본 프레임과 동일 픽셀 좌표에 제안 영역을 회색으로 가린 미리보기를
함께 전달한다. 숫자 좌표만 보고 승인하지 않고 글자 끝·외곽선이 영역 밖에 남는지와
제품·동작이 가려지는지를 비교한다. 원본 증거는 수정하지 않는다. 실제 출력에서 남은
글자를 발견하면 기존 결과를 보존하고, 필요한 구간을 더 좁혀 별도 제안·독립 승인과
새 제작 버전으로 보정한다. 잘못 승인된 구간은 같은 파일의 공유 검증 캐시에서도 제외한다.
새 정책은 종전 정책의 공유 캐시를 그대로 재사용하지 않으며, 이미 저장된 제작 결과는
보존한다. 표본 검토가 전체 프레임의 완벽한 가림을 보증하지는 않는다.
# 플랫폼 수집 제외 설정

`data/source_collection_policy.json`의 `disabled_platforms`에 플랫폼 ID와 제외 사유를
저장하면 해당 플랫폼의 자동 검색과 새 다운로드를 제외한다. 검색 엔진·이전 후보에서
발견한 URL에도 적용한다. 제외는 로그인/CAPTCHA 상태와 별개이고 실패 횟수로 세지 않는다.
로그인 기능, 수집 구현, 기존 영상과 세션은 보존하며 해당 항목을 제거하면 다시 활성화된다.
## 저장된 시계 소스의 재검색

저장 소스 검색은 손목시계의 다국어 이름과 `AQ230`, `casiowatches`,
`vintagewatch`, `Analog-Digital` 같은 실제 제목·해시태그 표현도 후보로 연결한다.
같은 브랜드라는 이유만으로 계산기 등 다른 제품을 시계 후보로 가져오지 않는다.
이 검색 결과는 미검증 후보이며 과거 기능·블러 승인이나 사용 가능 수량을 이어받지
않는다. 현재 레퍼런스에 대한 영상·핵심 기능·중복·블러 검사를 통과해야 소스로 집계한다.

## 다운로드 시간 배정

여러 후보에게 남은 플랫폼 시간을 균등하게 나누면, 메타데이터 조회·요청 간격·실제
파일 수신에 필요한 시간보다 개별 제한이 짧아질 수 있다. 실제 빌리빌리 파일이
다운로드 중인데 약 24초에서 잘리는 사례를 확인했다. 후보별 유효 시간은 최대
60초를 기준으로 확보하되, 설정된 후보 상한이 더 작으면 그 값을 따르고 플랫폼별
잔여 시간과 전체 라운드 잔여 시간도 넘지 않는다. 남은 후보는 다음 회차의 미검증
후보로 넘길 수 있다. 플랫폼 상한·전체 상한·요청 간격·인증 차단 중지는 유지한다.
시간 배정 변경만으로 파일 확보나 소스 품질 통과를 완료 처리하지 않는다.

## 저장 소스 제목의 표현 차이

한글 검색 표현은 띄어쓰기 없이 붙은 해시태그도 후보로 찾는다. 다진 마늘은 실제
저장 제목의 `minched garlic`, `freezing garlic`, `大蒜`을, 비즈 키링은 네잎클로버·
네잎크로버·행운키링 등의 표현을, 운동화는 `newbalances9060`을 기존 주제에 연결한다.
영문 단어 경계 검사는 유지한다. 제목 검색은 후보 발견만 담당하며 제품·기능의
일치를 보장하지 않는다. 신규 작업의 실제 파일·중복·핵심 기능·사용 구간 검사를
통과한 결과만 수량에 반영한다. 저장 파일 재발견은 새 외부 다운로드로 기록하지 않는다.

## 동일 파일의 글자·블러 검사 재사용

다른 제작 작업에 저장된 `source-mask-checks/<SHA256 앞 20자리>`의 완료 검사를
자동으로 찾는다. 현재 파일의 전체 SHA256, 검사 정책, 원본 파일과 모든 표본 프레임의
해시, 제안 지문, 캔버스와 승인된 정확한 구간을 다시 확인한 경우만 재사용한다.
깨진 JSON, 누락·변경·삭제된 증거, 다른 정책이나 파일의 검사는 캐시 미스로 처리하고
일반 시각 검사를 수행한다. 현재 작업의 ID·파일 경로·출처·권리 기록은 유지하며,
완료 표시는 제안과 승인 기록을 저장한 뒤 마지막에 쓴다.

재사용 대상은 동일 영상의 글자 영역과 검사 구간이다. 이전 레퍼런스에 대한 기능
승인을 옮기지 않는다. 현재 대본·주제의 핵심 기능은 승인된 구간에서 별도로 검사하며,
소스 개수나 플랫폼 최소 수량을 이 캐시만으로 충족 처리하지 않는다.

## 빈 화면과 구매 페이지의 장면 선택

실제 첫 표본이 거의 균일한 흰색·검은색 전환 화면이면 그 구간을 우선 선택하지
않는다. 흰 배경 위 실제 제품처럼 대비와 물체가 보이는 프레임은 이 조건에 해당하지
않는다. 시각 관찰은 제품·인물·쇼핑 웹 인터페이스·전환 화면을 구분하고, 쇼핑 페이지나
빈 전환 구간을 대본의 장면 순위에서 제외한다. 특정 유명인을 언급할 때 확인되지 않은
다른 인물의 모습으로 대신 표현하지 않고 실제 제품 장면을 보조로 사용한다.

이는 대본을 다시 쓰거나 중간 승인·제작 보류를 만드는 기준이 아니다. 일반 제품·사용
상황의 대체 장면을 선택하고, 모든 표본이 부적합한 예외에서는 미확인 임시 배치임을
명시한다. 완성 영상에서 실제 누락을 확인하면 이전 결과를 보존하고 별도 버전으로
장면을 교체하거나 잘못 승인된 구간을 철회한다. 철회는 새 구간 승인을 부여하지 않는다.
출력 화면 검토에서 결함이 확인된 소스 구간은 `data/source_review_withdrawals/<SHA-256>.json`에 실제 출력 근거와 함께 보존한다. 이 제외 기록은 검토 정책 버전과 독립적으로 같은 파일의 수집 검토 및 저장된 편집 계획에 적용한다. 제외 범위와 겹친 승인 구간은 잘라서 자동 승인하지 않고 전체 구간을 제외하며, 남은 구간의 기능 검토는 다시 수행한다. 기존 완성 MP4와 과거 검토 기록은 보존한다.
