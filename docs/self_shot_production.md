# 내 촬영 영상으로 쇼츠 제작

제작실 상단의 **내 촬영 영상으로 새 제작**에서 독립적인 작업을 만든다.
터진게시물의 선정·원본 다운로드·발화 추출 없이 시작하며, 대본 이후의
개인 복제 음성·장면 선택·자막·CapCut 프로젝트·MP4 내보내기는 기존 제작실을 사용한다.

## 사용 흐름

1. AI 집필 또는 직접 대본 입력을 선택한다.
2. AI 집필에는 주제/제품명을 입력한다. 제품 링크, 핵심 특징, 실제 사용 경험,
   댓글 키워드는 선택이다. 실제 확인한 같은 제품의 조사 사실과 입력 정보만 집필에 전달한다.
   조사 실패는 입력 정보로 계속 집필하며, 미완료 안내와 출처를 제작 정보에 남긴다.
3. 직접 입력한 대본은 문장 수정이나 CTA 추가 없이 음성·자막의 원문으로 사용한다.
4. 작업을 만든 뒤 촬영 영상을 추가한다. 작업당 최대 20개, MP4/MOV/WEBM,
   파일당 512MB라는 기존 업로드 기준을 사용한다. 실패한 파일만 다시 업로드할 수 있다.
5. 사용할 후보를 체크하고 **선택한 촬영 영상으로 제작 시작**을 누른다.
   촬영 영상 한 개부터 시작할 수 있다. 중간 대본·음성 승인 없이 완성 초안까지 진행한다.
6. 기존 제작실의 대본·목소리·장면·자막 수정과 버전 비교·다운로드를 사용한다.

AI는 후보의 일부 구간만 사용할 수 있다. 소스 선택에서 제외한 파일은 편집에 전달하지 않는다.
외부 영상은 검색·다운로드·보충하지 않으며 외부 소스 수량/플랫폼 기준은 적용하지 않는다.
부족한 길이는 촬영 구간의 반복으로 채우고 실제 재사용 구간을 계획과 결과 화면에 표시한다.
동일 파일 업로드는 해시로 중복을 제거하며 20개 제한을 소모하지 않는다.

## 구현 경계

- `studio_self_shot.py`: 독립 생성·제작 정보 수정·시작·제품 근거 준비·신규 집필.
- `POST /api/studio/self-shot`: 클라이언트 생성 키를 통한 멱등 생성. 업로드 이전에는 큐를 실행하지 않는다.
- `POST /api/studio/{id}/save-self-shot-brief`: 제작 시작 전 입력 수정.
- 기존 `upload-source` / `use-sources`와 workflow 버전·복구·재제작을 공유한다.
- `creation_mode=self_shot`와 별도 owned-only 소스 정책으로 외부 소스 수집을 차단한다.
  DB의 shortcode 칸에는 기존 고유 인덱스와 호환되는 `own-<생성키>`를 저장하지만,
  이를 Instagram 게시물로 조회하지 않는다.
- `writing/product_research.py`: 별도 Codex 조사 작업만 웹 검색을 허용한다.
  근거·출처를 저장하고 같은 제품으로 확인된 자료만 텍스트 집필에 전달한다.
  일반 집필기는 기존처럼 검색·셸 도구를 사용하지 않는다.
- 공통 `writing/RULES.md`에 신규 제품 후킹에 필요한 원본 비참조 예외를
  `writing/contract.py`에서 추가해 해시로 기록한다. 기존 벤치마크 계약은 유지한다.
- Auto CapCut 별도 프로세스의 `owned-only-reuse-v1` 계획이 반복 구간·실제 움직임의
  루프와 결과 표시를 담당한다. 사용자가 편집한 기존 프로젝트를 덮어쓰지 않는다.

## 검증

`tests/test_studio_self_shot.py`, `tests/test_studio_self_shot_browser.py`에서
게시물 없는 생성, 입력 보존, 20개 제한/중복, 선택 제외, 개인 음성 기본,
조사와 집필 경계, 완성·재제작·기존 버전 보존 및 데스크톱/모바일 UI를 검증한다.
Auto CapCut의 `tests/test_owned_footage.py`는 실제 FFmpeg 영상의 반복되는 움직임,
길이, 음성 원본 보존 및 편집 가능한 초안 출력을 검증한다.

2026-10-07 검증: 신규 기능과 관련 백엔드·브라우저 검사 152건,
Auto CapCut의 소유 영상·타임라인·자막 검사 18건이 통과했다.
전체 제작실 브라우저 검사에서는 기존 화면의 접힌 도구·변경된 안내 문구 등을
기대하는 검사 10건이 실패했다. 소스 패널의 접힌 안내를 즉시 찾는 대표 실패는
신규 제작 진입 UI를 제외한 정적 화면에서도 재현했다.
실제 사용자 촬영 영상으로 만드는 통합 제작은 아직 실행하지 않았다.

같은 날 저장된 테스트 영상 20개를 브라우저에서 업로드하여, ‘다진 마늘 소분
냉동 보관통’ 주제로 개인 복제 음성 서비스를 포함한 실제 전체 제작을 완료했다.
작업 `work-f5fbc67539ec4fd1`은 115개 후보 장면 중 영상 5개를 사용해
14.87초, 1080×1920 H.264/AAC MP4와 자막 17개를 만들었다.
21번째 업로드 차단, 외부 영상 수집 없음, 대본·음성 발화·자막 일치,
음성 원본 해시 보존, 전체 MP4 디코딩, 브라우저 재생 및
MP4·CapCut ZIP·대본 TXT 다운로드를 확인했다. 브라우저 콘솔 오류는 없었다.
CapCut이 열려 있어 프로젝트 등록은 보류하고 웹 렌더링으로 완료했으며,
편집 가능한 프로젝트 ZIP도 정상 생성했다.

실제 제작 중 선택 후보 전체를 ‘현재 영상에 사용됨’으로 표시하던 오류와,
독립 제작 완성 화면에 ‘원본 영상이 없습니다’ 비교 패널을 표시하던 오류를 수정했다.
관련 소스 패널·워크스페이스 회귀 검사 17건이 통과했다.
테스트 영상은 PC에 저장된 기존 영상의 복사본이며 사용자 직접 촬영물로
주장하지 않는다. 기존 자막·워터마크와 일부 맥락 장면은 테스트 결과에도 남는다.
