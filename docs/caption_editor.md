# 제작실: 즉시 자막 편집과 내보내기

사용자 작업은 **소스 준비 → 대본·목소리 → 미리보기·내보내기** 세 화면으로 묶는다.
내부의 여섯 처리 단계와 기존 작업·출력 버전은 유지한다. 원본 발화는 대본 화면에서
필요할 때 펼쳐 교정한다. 웹에서 지원하는 편집은 자막 문구와 시작·끝 시간이다.
장면 선택·강조·효과 편집은 CapCut 경로를 사용한다.

## 사용자의 동작

- 자막 ±0.1초 및 문구 변경은 자막 없는 영상 위의 캔버스에 즉시 반영된다.
  음성과 장면 시간은 바뀌지 않는다. 구간 재생은 앞뒤 0.4초를 포함한다.
- `편집 저장`은 서버에 편집 내용을 보관한다. MP4를 생성하지 않는다.
- `수정본 MP4 내보내기`는 마지막 입력 전체를 한 요청으로 검증·저장하고,
  그 시점의 편집 내용을 복사한 새 출력 작업을 만든다. 별도 재제작 클릭은 없다.
- 변경이 없고 출력 파일이 있으면 `현재 MP4 다운로드`로 기존 파일을 받는다.
- 내보내기 중 작성한 추가 입력은 보존된다. 새 출력 버전이 준비되면 이전 입력을
  자동 적용하지 않고 사용자가 확인하도록 안내한다.
- CapCut에서 직접 수정한 프로젝트는 덮어쓰거나 웹에 자동 역수입하지 않는다.
  웹의 자막 변경을 먼저 내보내면 그 버전의 별도 프로젝트를 열 수 있다.

## 계약과 구현

`prepare-caption-preview`는 기존 `body.mp4`와 미리보기의 오디오를 인코딩 없이 합친다.
새 제작에는 `clean_preview_path`가 자동으로 포함되고, 기존 제작은 준비 버튼으로
추가한다. 소스 영상에 원래 포함된 글자나 첫 프레임 표지는 제거하지 않는다.

`save-captions`와 `export-edit`는 현재 `edit_id`, `feedback_revision`, 자막 변경 목록을
검증한다. 시간 겹침, 범위 초과, 다른 대본·소스·음성 피드백과의 충돌은 출력 전에
차단한다. 저장 버전과 출력 작업은 분리되어 중간 입력이 실행 중 작업을 바꾸지 않는다.

내보내기는 auto_capcut의 별도 Python 프로세스에 `caption-export`를 전달한다.
소스 수집, 대본 작성, TTS, 장면 분석은 재실행하지 않는다. 기존 영상·음성을 재사용해
새 자막만 합성하고, 동일 타임라인의 독립된 CapCut 프로젝트를 만든다.
1080×1920, 30fps, 음성 스트림, 길이를 검사한 뒤 출력 완료로 처리한다.
이 경로에서는 CapCut 앱 실행·등록을 출력의 선행 조건으로 두지 않는다.

브라우저 프레임 콜백으로 시간에 맞춰 자막을 표시한다. 서버와 같은 폰트·좌표·강조색을
사용하지만 브라우저와 ASS의 글자 가장자리 표현은 미세하게 다를 수 있다.
지원하지 않는 구형 서버에서는 새 편집 기능을 비활성화하여 요청이 조용히 무시되지 않게 한다.

## 검증

- 실제 인코딩 프레임에서 0.1초 이동 전후 자막 유무 확인.
- 출력 전후 디코딩한 음성 일치, 승인 음성 파일 해시 보존 확인.
- CapCut 프로젝트 자막 시간과 출력 타임라인 일치 확인.
- 브라우저에서 즉시 캔버스 변화, 실행 취소, 저장·재접속, 최종 입력 내보내기 확인.
- 서버에서 동시 내보내기·오래된 편집 버전·피드백 충돌 차단 및 대본/TTS 재사용 확인.
