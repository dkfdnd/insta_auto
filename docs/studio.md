## 실행과 현재 테스트 자료

기존 VoiceBench를 실행한 상태에서 hotpost 저장소의 가상환경을 사용한다. 다른 서비스와 충돌하지 않는 포트를 선택한다.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m hotpost serve --host 127.0.0.1 --port 8767 --no-browser
```

제작실 주소: http://127.0.0.1:8767/studio.html

- 소재 탐색에서 여러 동영상을 선택하고 제작실에 추가한다.
- 작업별로 대본을 저장·수정하고 승인한다. AI 수정안은 비교 후 적용한다.
- 생성된 **최종 사용 음성**을 듣고 승인한다. 속도 조절은 승인 전에 파일에 반영된다.
- 초안을 재생하고 자막·시간·장면·강조를 수정한다. 자연어 요청에는 재생 위치 또는 선택 구간을 연결한다.
- 장면 교체는 실제 확보한 후보를 보고 선택한다. 직접 보여주는 장면과 대체 장면을 구분한다.
- `CapCut에서 직접 편집`으로 결과를 연다. 새 초안 등록 시에는 CapCut의 현재 작업을 저장하고 앱을 닫아야 한다. 다시 버튼을 누르면 등록을 재시도한다. 앱을 강제 종료하지 않는다.

검증 후 남겨둔 작업은 대본 검토 2건, 음성 검토 1건, 초안 검토 1건이다. 가방 작업 `work-7700ddd3d01c442a`에는 실제 음성·영상과 편집 버전 4개가 있다. 치킨 작업 `work-3d6c0b4dad6d4008`은 실제 음성만 생성한 승인 대기 상태다.

## 저장·승인·복구 계약

- `data/studio/studio.sqlite3`: 작업, 단계 실행 큐, 이벤트를 SQLite WAL로 저장한다. 결과 파일은 같은 폴더 아래 작업 ID별로 남긴다.
- 대본·음성·편집 결과는 독립 버전이다. 현재 선택과 승인된 버전 ID를 별도로 관리한다.
- 대본이 바뀌면 현재 음성·편집 연결 및 승인을 해제하되 이전 버전은 보존한다. 늦게 완료된 이전 작업은 새 승인 결과가 되지 않는다.
- 음성 재생성 중 이전 음성을 승인할 수 없다. 승인 시 최종 WAV의 SHA-256을 확인한다.
- 중복 클릭은 실행 키로 중복 작업을 막고, 대본 저장은 revision 충돌을 검사한다.
- 서버 재시작 시 저장한 VoiceBench 요청 ID로 이어받는다. 실행기 결과 파일과 OS 잠금을 이용해 이미 진행·완료한 렌더를 재사용한다.
- 한 서버만 제작실 실행 권한을 가진다. 승인 대기는 실행 스레드를 점유하지 않는다. 실제 렌더는 순차 실행한다.
- 기존 hotpost 자동 제작 감시는 새 서버 실행 경로에서 시작하지 않는다. 이전 결과물은 보존한다. 이미 떠 있는 이전 버전 서버는 코드가 자동 교체되지 않으므로 별도 운영 상태를 확인한다.
- 데이터 백업에는 DB만 복사하는 대신 WAL을 포함하거나 서버가 유휴 상태일 때 SQLite 백업 API와 작업 폴더를 함께 보존한다. 앱 재설치나 초기화를 복구 방법으로 사용하지 않는다.

## 코드 경계

| 구성 | 역할 |
| --- | --- |
| `hotpost/studio_store.py` | 트랜잭션, 작업 큐, 버전 참조, 체크포인트 |
| `hotpost/studio.py` | 승인 상태 전이, 단계 실행, 버전 검증 |
| `hotpost/studio_http.py` | API, Origin 검사, 미디어 Range 응답 |
| `hotpost/studio_ai.py` | 대본 제안, 실제 프레임 의미 분석, 구간 수정 해석 |
| `web/studio.*` | 제작 목록, 검토·승인, 재생·수정 UI |
| `auto_capcut.studio_runner` | 버전된 JSON 요청/결과와 실행 잠금 |
| `auto_capcut.core.studio_timeline` | 승인 음성 정렬, 자막 분할, 장면 후보와 편집 계획 |
| `auto_capcut.core.studio_render` | 공통 계획 기반 미리보기·CapCut 초안 |

VoiceBench는 기존 HTTP API, Auto CapCut은 별도 Python 프로세스와 JSON으로 연결한다. 환경이나 패키지를 직접 통합하지 않는다. API 키, 모델, 엔진, 레퍼런스, Seed는 제작실이 바꾸지 않는다.

## 편집 품질의 범위

- 자막은 실제 글꼴 폭과 의미 단위로 분할하고, 사용자가 지정한 줄바꿈을 보존한다. 최종 승인 음성에서 얻은 ASR 단어 시각과 대본 문자 대응을 사용한다. ASR 일치율이 높아도 실제 발화 시작 시각이 완벽하다는 뜻은 아니다.
- 첫 프레임 커버는 30fps의 첫 프레임을 대체하므로 음성·자막을 뒤로 밀지 않는다.
- 장면 분석은 각 소스의 제한된 구간을 골라 구간별 실제 프레임 3장을 사용한다. 전체 영상을 촘촘히 검색하지 않으므로 적합한 짧은 장면을 놓칠 수 있다.
- 적합한 장면을 찾지 못하면 대체 장면으로 완성하고 확인 표시를 남긴다. AI가 붙인 직접 근거 분류도 사용자가 확인해야 한다.
- 강조는 선택한 지점의 화면 확대·자막 크기/색상·자체 생성 효과음이다. 복잡한 CapCut 전환/애니메이션 라이브러리 전체를 지원하지 않는다.
- 자막·음성·효과음은 CapCut에서 별도 트랙으로 편집할 수 있다. 화면 확대는 영상 클립에 반영되어 있어 CapCut의 효과 슬라이더로 되돌릴 수 없고 제작실에서 새 버전을 만들어야 한다. 글꼴 렌더링에는 미세한 차이가 남을 수 있다.
- 원 출처 URL·권리 상태는 manifest에서 유지한다. 신규 계획과 초안에 출처 기록을 전달한다. 이전 초안 파일은 소급 수정하지 않는다.
- 자연어 수정은 구현된 자막/시간/후보 선택/강조 범위에 한정된다. 음성의 구간 재생성과 감정 지시 기능은 지원하지 않는다. 같은 대본은 VoiceBench의 기존 결과를 재사용할 수 있다.
- 대본의 사실성·말투와 최종 음성 자연스러움은 사용자 승인이 필요하다. 자동 검토가 제품 사실을 보증하지 않는다.

## 검증과 사용자 테스트

자동 검사는 승인 관계, 오래된 결과, 저장 충돌, 재접속, 중복 렌더, 미디어 탐색, 타임라인 수정과 실제 FFmpeg 출력에 집중한다. 실제 브라우저와 CapCut에서도 재생·편집 가능 여부를 확인했다.

다음 사용자 테스트에서는 생성 개수 대신 **대본 검토 + 음성 청취 + AI 수정 요청 + CapCut 편집의 총 직접 작업 시간**을 기록한다. 자막 재분할·싱크 수정·장면 교체·재생성 횟수를 함께 비교한다. 이번 구현만으로 시간이 얼마나 절감됐는지는 아직 측정하지 않았다.
