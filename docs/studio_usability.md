# 제작실 사용성 개선

컴퓨터 사용이 익숙하지 않은 사용자가 도움 없이 다음 행동을 찾는 것을 목표로 한다.
실제 사용자 참여 시험을 대신하는 결과가 아니라, 브라우저 기반 과업 점검이다.

## 구현 순서와 완료 기준

1. 실행 취소: 자막 값과 변경 표시, 파일 저장 버튼, CapCut 사용 가능 상태가 함께 복원된다.
2. 제작 동선: 대본·속도·발음·영상 선택을 한 번의 요청으로 검증·저장하고 새 영상을 만든다. 잘못된 값이나 충돌은 전체 요청을 취소하며 기존 완성본을 보존한다.
3. 상태 표시: 수정 중인 대본과 기존 완성본을 구분한다. 요청 중 중복 클릭을 막고 이후 추가 입력은 보존한다.
4. 완성본 찾기: 완성 영상 보기 버튼은 실제 영상 플레이어로 이동한다.
5. 작업 목록: 확인 필요 / 제작 중 / 완성의 세 묶음을 사용한다. 내부 6단계는 펼쳐 보는 정보로 둔다.
6. 편집 화면: 대본을 먼저 배치하고 원본 음성 인식 교정은 아래 참고 영역으로 옮긴다. 개별 보관은 선택 기능이며 제작 전 필수 절차가 아니다.
7. 모바일: 작은 영상 미리보기를 고정하고 자막을 하나씩 선택한다. 이전·다음 및 직접 선택을 제공하며 모든 자막 값은 유지한다.
8. 가독성: 본문 입력 16px, 설명 14px, 조작 영역 44px 이상과 키보드 포커스 표시를 사용한다. 휴대폰 높이가 짧을 때는 고정을 해제한다.
9. 목소리: 현재 외부 연동은 VoiceBench의 고정 기본 음성을 사용한다. 웹 갤러리의 선택이 외부 자동 제작에 전달되지 않으므로 제작실에서 선택 가능한 것처럼 표시하지 않는다. 이 제한과 속도·발음의 적용 범위를 명시한다.

## 판단 근거

- [W3C 명확한 레이블](https://www.w3.org/WAI/WCAG2/supplemental/patterns/o4p06-clear-labels/): 버튼은 누른 후 생길 결과를 설명한다.
- [NN/g 사용성 원칙](https://www.nngroup.com/articles/ten-usability-heuristics/): 상태를 보여주고, 기억보다 인식을 돕고, 실행 취소와 오류 회복 경로를 제공한다.
- [WCAG 조작 영역](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html): 최소 기준보다 넉넉한 44px을 설계 목표로 사용한다. 글자 크기 자체가 WCAG 준수를 보장하지는 않는다.

## 검증 범위

자동화된 브라우저 시험은 실제 페이지와 격리된 API를 사용하여 입력 보존·상태 전환·자막 조정·모바일 배치를 확인한다. 백엔드 시험은 데이터베이스 트랜잭션, 충돌 및 재제작 큐를 검증한다. 운영 중인 작업에 테스트 대본을 저장하거나 음성 생성을 요청하지 않는다.
