# 제작실 UX 계약

제작실은 터진게시물에서 고른 소재를 우리 영상으로 만드는 작업 공간이다. 두 화면은 주황색 강조색과 테마 설정을 공유한다. 내부 게시물 ID를 제목으로 노출하지 않는다.

## 작업의 중심

- 카드와 상세 상단은 현재 단계, 실행/대기/실패 상태, 다음 행동을 함께 표시한다. 단계 완료 수와 실제 실행 여부를 분리하고, 실행 중인 작업에만 로딩 애니메이션을 사용한다.
- 상세의 주 작업 영역에는 현재 할 일을 배치한다. 좌측 단계 이동과 탭은 테두리가 있는 버튼이다. 모바일에서는 단계 목록을 기본으로 접고 업로드/편집 공간을 확보한다.
- 영어 예외와 로컬 경로는 사용자 경고로 그대로 출력하지 않는다. 알려진 오류는 한국어 원인·대응으로, 미분류 기술 오류는 한국어 안내로 표시한다. 원래 오류는 서버 상태/기록에 유지한다.
- 대본은 편집기·저장·AI 수정 요청이 우선이다. 원본/후보와 문장 검사는 접어서 제공한다. 음성은 청취와 속도가 우선이고 발음 교정은 고급 옵션이다. 편집은 영상 미리보기와 장면/자막을 우선하고 AI 구간 요청·타이밍/강조·선택 근거는 접어 둔다.

## 영상 추가와 이어가기

- `source-upload.js`는 다중 파일 선택과 드래그앤드롭을 같은 파일별 대기열로 처리한다. 기존 단일 파일 HTTP 업로드 API에 순차 전송하므로 파일별 진행률/영상 검증/부분 실패/실패 파일 재시도가 가능하다.
- MP4, MOV, WEBM, 파일당 최대 512MB. 클라이언트 검사에 이어 서버가 실제 영상과 길이를 검증한다. 중복 콘텐츠는 서버 해시로 중복 저장하지 않는다.
- 대기열과 File 객체는 작업 패널별 메모리에 두며 다른 작업으로 전환해도 서로 섞이지 않는다. 페이지 자체를 떠날 때 업로드 또는 미저장 편집이 있으면 브라우저의 이탈 확인을 사용한다. 파일 선택 자체를 디스크나 localStorage에 저장하지 않는다.
- 업로드는 자료 보관이다. `선택한 영상으로 제작 이어가기`가 명시적 실행 행동이다. `POST /api/studio/{id}/use-sources`는 파일 존재·선택 ID·현재 단계·실행 중인 작업·revision을 검사한 뒤 자료 준비를 예약한다. 원본 전사와 재가공 규칙을 생략하지 않는다.
- 자료 준비는 선택한 로컬 영상을 우선하며 다시 외부 소스 검색으로 돌아가지 않는다. 기존 실패/대기 자료 준비 작업은 정리하고 새 준비 작업 하나를 만든다. 작업 도중 추가 업로드가 도착해도 결과 반영 시 지우지 않는다. 출처와 사용자 업로드 표시는 유지한다.
- 다음 단계까지 진행된 영상은 기존 소스 선택 저장 → 재제작 흐름을 사용한다. 진행 중인 작업에 소스를 몰래 교체하지 않는다.

## 업로드 이후 수정과 검토

- 원본 발화 영역은 원본 영상의 시간별 자동 전사와 OCR을 분리한다. 연결된 원본 파일만 작업 미디어 API에서 재생할 수 있다. 원본 파일이 없으면 그 상태를 안내한다.
- 발화 교정본은 `reviewed_original_text`와 교정 이력에 별도로 저장하며 자동 인식 원문을 덮어쓰지 않는다. 교정본은 다음 문장 검사·AI 수정 요청의 근거로만 쓰인다. 이미 실행 중인 자동 제작이나 현재 대본을 자동 변경하지 않는다.
- AI 수정 요청은 화면에 입력한 대본을 명시적으로 전달한다. 요청 당시 대본과 수정안을 비교하며, 이후 대본 또는 원본 발화가 달라지면 낡은 수정안을 적용하지 않는다. 입력 중에도 완료된 수정안은 표시한다.
- AI 대본·구간 요청 옆에서 준비 중, 실패 원인과 재요청 방법, 완료 후 비교/재제작 행동을 표시한다. 입력·재생 중에도 상태가 갱신되고, 진행 중에는 중복 요청을 막는다. 검토에서 거절된 수정안은 현재 대본에 적용되지 않는다.
- 대본·속도·발음·소스·구간 피드백은 저장 상태와 다음 재제작 범위를 표시한다. 음성에는 읽은 대본·속도·길이를, 편집에는 구간 대사와 자막을 함께 표시한다. 자막 수정은 음성을 수정하지 않는다.
- 대본·음성·소스 변경과 기존 구간 수정을 함께 재제작할 수 없다. 구간 수정만 초기화하여 상위 단계 변경을 적용한 뒤 새 타이밍에서 구간을 수정한다. 이전 완료본은 보존한다.
- 구간 입력은 표시 당시 편집 ID에 연결한다. 폴링 또는 새로고침으로 새 편집본이 도착해도 이전 입력을 새 구간에 적용하지 않는다. 이전 입력을 별도로 확인·복사한 뒤 구간 입력만 비울 수 있다.
- 저장 응답을 기다리는 동안 추가로 입력한 내용과 다른 섹션의 미저장 내용은 유지한다. 후보 선택·대본 복원은 직접 입력을 먼저 저장하도록 안내한다.
- 결과 생성 완료와 사용자 검토 완료를 구분한다. 발음·자막·장면 확인 기록은 해당 최종 결과 버전에만 귀속되고 새 버전에 승계되지 않는다.

## 검증 범위

- `test_studio_board_browser.py`: 단계 보드, 입력/재생 보존, 다중 선택, 드롭, 부분 실패 후 재시도, 선택 소스 전달, 모바일 접근, 내부 ID·영어 오류 비노출, 실제 MP4 2개를 격리 HTTP 서버로 업로드/검증/미리보기/재개.
- `test_studio_workflow.py`: 자동/수동 작업의 업로드 소스 재개, 재검색 금지, 동시 업로드 보존, 선택·출처 유지, 잘못된 단계/실행 중 재개 거절.
- 기존 대본·음성·편집·결과 버전 테스트와 전체 회귀 테스트를 함께 실행한다. 시스템의 동작 줄이기 설정에서는 애니메이션을 중지한다.

### 2026-09-30 로컬 통합 확인

실제 실행 중인 제작실에서 원본 발화 교정, 대본 저장, 속도 1.05배·발음 교정, 장면 교체, 자막·타이밍·강조 변경, AI 구간 수정과 재제작을 확인했다. 잘못된 자막 시간은 400으로 거절됐고 정상 입력은 다음 버전에 반영됐다. 자막·장면만 바꾼 버전은 기존 음성을 재사용했다. CapCut 최종 MP4 두 버전은 1080×1920·30fps·음성 포함·7.569초로 검증했다.

클라우드 키가 없을 때 제작실 검토가 중단되던 경로는 script_auto의 인증된 로컬 `/api/editorial/jobs`로 연결했다. 웹 조사는 해당 경로가 대신하지 않는다. 질문·제안이나 근거 없는 주장 삭제까지 자료 부족으로 거절하던 대본 검토 지침도 구분했다. AI 결과는 사용자 비교·선택을 거치며, 작은 화면 글자와 장면 설명의 오인은 남을 수 있다.

원본 전사 도구 누락을 로컬 환경에서 복구했고, 전사 실패 시 분석용 원본과 실패 안내를 먼저 남기도록 바꿨다. 의미 없는 소스 검색 오류가 원본 음성 문제를 가리지 않는다. 테스트 영상은 내부 검증용이며 외부 게시나 사용자 검토 완료 처리를 하지 않았다.
